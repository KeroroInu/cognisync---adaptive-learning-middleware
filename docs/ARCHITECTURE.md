课堂包按 `configuration.worksheet.lesson_id` 关联阶段，`provenance` 保存阶段/模板/公共材料版本；不是按班级 session 推断课时。新包提供短任务单，停止生成未填写的第二份空白 worksheet.md，历史已保存版本仍随包保留。教师资料 ZIP 仅核对，不伪造学生账号绑定；真实学生包仍通过认证下载动态组装。研究原件不执行、不自动判作掌握。

## 2026-10-08 当前入口与轻量化边界

共同学生工作台 → 本机 SFLS 创作 → ZIP 收件 / README 只读投影。界面不按班级分流，不强制重复填写网页任务单；两班共享工具与智能体支持。教师主入口为任务、测试与量表、学生、导出。旧任务单及分组启动 UI 已删除；以下相关章节为历史数据兼容说明，不是当前入口。

设计：TaskDesign 保存 requirements 与 drawio_xml 到既有不可覆盖版本；旧 nodes/edges 仍可读取。DrawioEditor 使用同源静态 iframe、核对消息源窗口与来源；XML 有大小、页数和声明限制。设计下载输出原始 .drawio、架构 JSON 和供文本模型理解的 Markdown 摘要，不执行其内容。画板使用官方嵌入协议：https://www.drawio.com/docs/reference/embed-mode/ 。

作品：GET /api/materials/{id}/readme 只读取当前登录学生在本班有效任务下最近提交的 project/README.md，最大预览 64 KiB。返回 no-store，在网页按纯文本显示，不执行 HTML、不请求图片、不新增模型调用、不改原 ZIP。文字来源保留为提交作品，不等同于能力证据。研究分析仍需对照对话、运行及版本记录。

删除学生 Worksheet 组件、旧自绘画板编辑 UI、教师 LessonSetup / Dashboard / PracticeReview / ProjectReviewPanel 及重复 WorksheetReview。保留数据模型与导出兼容，未清库。既有数据库与服务未变；“轻量”指入口和运行负担减少，不表示数据库依赖已经移除。

更新日期：2026-10-07。本文以当前代码为依据，区分实现、验证与未来设想。教学目标见[教学与研究设计](TEACHING_DESIGN.md)，测试和启动见[开发与运行](DEVELOPMENT.md)。第 10 节记载旧网页共同帮助路径；以下 SFLS 增量优先于历史入口说明。

当前主线为“统一平台任务工作台＋本地 SFLS”：平台保管身份、教师发布、学生需求/架构版本及收件；SFLS 独立仓库用固定 Pi SDK 在学生机器运行代码与工具、调用模型、收集本课证据。平台没有每学生 Agent 进程或桌面容器。任务列表低频轮询，画板与编辑器按需加载，绘图拖动本地处理、草稿防抖，保存/下载/提交才写服务器。不能仅据架构声称 4 GB 服务器足够整班：原 PostgreSQL＋Neo4j 服务仍在，需实测并规划附件存储。

`materials.py` 沿用材料/收件接口，新增 `runtime=sfls` 与设计 GET/POST；`task_design.py` 管不可覆盖的 PreparationRecord 设计版本；`sfls_package.py` 只组包和检查，不执行学生代码；`sfls_evidence.py` 为已上传日志生成原件引用索引。平台前后测 design scope 为 material_id，课堂为 project_id，均绑定登录用户。旧课堂网页及其浏览器运行器保留为可选工具，SFLS 支架唯一来源为 PI_SFLS 的 `src/scaffold.ts`，不读实验组切换规则。

### 共同任务单与证据版本（2026-10-07）

`services/worksheet.py` 管模板冻结、答案校验、不可覆盖版本、学生包内容及导出投影；`api/endpoints/worksheets.py` 管学生本人读写与教师本人发布任务的审阅。`Worksheet.tsx` 按需加载为两组共用三段表单，`WorksheetTools.tsx` 提供教师选课/版本和只读审阅。模板库在服务器，学生响应先剔除教学条件、教师评价参考和共同出口题，不将整库交给客户端或 SFLS。

数据链：教师发布冻结模板 → 学生显式保存 `PreparationRecord(kind=worksheet)` → 下载时冻结本人 current/plan 文件与哈希 → SFLS 本机使用 → 收件保留上传原件、下载绑定及网页当时版本 → 原始研究包与 `worksheets.jsonl/csv`。计划 action 创建 `plan_revision_id`，其后版本携带引用；它是明确选择的计划快照，不代表首次生成、编码前完成或独立作答。模板哈希包括教师配置，学生包仅带过滤后的内容及哈希标识。

保存按学生＋材料加事务锁，并核对 `expected_user_id`、请求 UUID 和 `base_revision`；冲突返回 409，前端保留草稿并让学生比较。浏览器缓存键含身份、材料和格式版本。列表分页读取，不新增逐字上传、模型调用、后台每学生进程或数据库表。新课不复制上一课答案；历史只读。课堂任务单不进入 pre/post 包，不改共同 SFLS 支架。

上传中的版本号仅记为 `submitted_version_unverified`；`matches_download` 只比较文件哈希，网页版本不回填覆盖已下载或交回的内容。资料收件与任务单当前网页状态可能不同，研究分析须按版本关联，不能将文本自报测试当作自动判题或能力测量。

以下为保留的网页编程工具架构，不再作为 SFLS 本机运行的描述：

当前课堂入口统一为 `ClassroomSnakeWorkspace`，不按组别分流。`data/basicSnake.ts` 是版本化教学源码与数据契约；`services/basicSnakeRunner.ts` 用既有 Worker 调度/沙箱调用真实学生函数；`BasicSnakeBoard` 只按返回的行列坐标绘制，不补函数或计算得分。编辑器与运行版本分开保存，草稿变更使预览暂停，显式运行才换版本。`BasicSnakeReviewPreview` 复用同一契约运行冻结作品。旧无运行版本标记的作品仍走旧预览器，不能仅凭函数名猜是哪套坐标/初始化协议。

保存使用新 `save-basic-snake` 原子事务，`workspace_data.basicSnake` 包含 runtime/code/revision/首次旧代码备份；根级历史卡片与模块保持原状。运行事件附不可覆盖代码版本；失败事件本机按学生、任务及事件 ID 隔离，刷新原 ID 补传。课堂连续运行由 `snakeLoop.ts` 的可取消异步 while 循环调度，每次等待浏览器 Python Worker 返回后再等待下一轮，WASD 只更新待执行方向；隐藏/编辑/离开/出错停止，无每帧后端请求。事件标明连续模式与每步方向，区别于真实按键次数；冻结作品回顾仍可逐步观察。编辑保存防抖并串行，AI 仍走共同队列/协议，不能因此推断已通过整班负载测试。

## 1. 当前是模块化单体，不是多智能体平台

```text
学生 React 界面 ── JWT + API ──┐
  └─ Pyodide Worker：代码运行  │
教师 React 界面 ── 管理 JWT ───┤
                              ▼
                     FastAPI 模块化后端
                       ├─ PostgreSQL：身份、任务、对话、版本、研究记录
                       ├─ Neo4j：知识图谱与当前画像相关信息
                       └─ 教学 Harness → 外部 LLM API
```

学生端和管理端均为 React 19 / TypeScript / Vite；代码编辑器为 CodeMirror。后端使用 FastAPI、SQLAlchemy 异步会话、PostgreSQL，知识图谱使用 Neo4j。当前 Compose 为 PostgreSQL 15、Neo4j 5.15；Neo4j Python 驱动版本不是数据库服务版本。

系统没有 Redis、每学生独立容器、后台完整桌面，也没有安装 Pi 作为平台执行引擎。分析、教学回复等职责由后端服务组织，不能因为存在几个服务类就声称是多个自主 Agent。

## 2. 教学 Agent Harness 的职责

这里的 Harness 指围绕模型建立的上下文、策略、能力约束、执行接口和记录机制；不是一个额外模型，也不是自主替学生操作电脑的代理。

一次教学请求沿以下路径组织：

```text
身份与任务权限 → 当前阶段/功能/代码/反馈 → 学生自己的历史与教材摘要
             → 阶段策略、允许能力和支架等级 → 规则回复或 LLM 回复 → 保存证据
```

[chat.py](../backend/app/api/endpoints/chat.py) 组织请求；[learning_agent_harness.py](../backend/app/services/learning_agent_harness.py) 处理当前情境；[scaffold_service.py](../backend/app/services/scaffold_service.py) 处理支架；[beginner_snake_templates.py](../backend/app/services/beginner_snake_templates.py) 提供基础模板；[creative_capability.py](../backend/app/services/creative_capability.py) 描述创意运行能力；[textbook_library.py](../backend/app/services/textbook_library.py) 提取教材摘要。

### 当前焦点优先，不混用别人的数据或别的函数

上下文应按学生、任务、阶段与功能焦点组织。前端当前代码与最近运行结果比另一张卡的旧对话更相关；保存工作区和阶段事件用于补充，不能只凭旧对话猜学生在哪一步。前端上报情境是交互证据，不是权限凭据，身份和可访问任务由后端确认。

| 当前阶段 | 可使用的主要资源 | 不应发生的行为 |
| --- | --- | --- |
| 运行与观察 | 当前运行状态、客观运行记录、学生观察卡 | 把观察卡为空当成从未运行；要求立刻修改函数 |
| 功能命名 | 学生观察、现有功能卡与覆盖数量 | 下发冻结蓝图整套功能答案，新增繁琐表单 |
| 单功能流程 | 当前功能卡、该卡节点与连线 | 猜测未选择的功能，把全局系统图当必修 |
| 编码建构 | 当前基础/创意函数、编辑器代码、可执行能力、测试反馈 | 给平台不支持的事件、状态字段或终端指令；把另一张卡的错误当当前错误 |

聊天历史按任务、阶段与焦点限定，不把所有学生记录拼进一次提示。信息缺失或保存未完成时，应明确说“目前没有读到”，不能据此断言学生没有做过。

2026-09-15 增补：单功能流程也把当前卡 ID 与该卡图示传入 Harness，历史不能混入另一张卡。[learning_evidence.py](../backend/app/services/learning_evidence.py) 注入统一的证据和帮助政策：区分记录、自述、推断；一次只问一个必要问题；针对语法、关系或验证困难回应，不把画像当诊断。仍是单次回复，不新增 Agent 或模型分析调用，也不保证模型绝对遵守提示。

新发布课次还绑定 `lesson_id`、`session_id` 和服务器核定的组别/任务；新课堂消息先按本课过滤，再按环节/功能聚焦，不调用跨课历史摘要。教师任务提示由服务器读取冻结快照，普通课堂对话也不信任客户端自行指定的教学提示。已有提交优先保留原蓝图版本；新提交使用课次发布版本。教师关闭任务 AI 仍可即时拒绝新请求，不因快照曾开放而绕过。

准备区使用独立的短上下文调用：当前代码、上次实际运行代码与输出、本人本课次最近六轮准备区对话。旧输出明确对应 `last_run_code`，不是自动代表当前编辑器版本。该入口不读取教师蓝图、课堂卡片或画像，不改画像算法；两组使用同一政策。共享既有模型队列，等待模型前提交并释放 SQL 事务；请求按用户＋请求编号幂等保存，不自动重发模型调用。

### 模型没有学生和教师的最终操作权

模型可建议、解释并给代码；学生决定采用、编辑、运行、保存和启用。AI 草稿不是自动形成的学生答案。支架 L3 的确认与后续讨论规则见教学设计；不自动替学生点击下一阶段或修改教师任务、量表和分组。

基础函数的部分回复可由规则模板直接产生；开放讨论与创意求助使用外部模型。它是受约束的单次请求流程，不是递归规划—执行—反思的无限工具循环。尚未实现跨学生调度的多智能体系统或任意文件编辑权限。

## 3. 教材、画像与模型请求的边界

教材库目前是[版本化核对摘要 JSON](../backend/app/resources/curriculum/hsd_data_computing.json)，包含七张摘要及出处信息。通过本地规则选择少量相关条目并缓存；不是全文向量库，也不需要每次再请求一个模型做检索。摘要之外的教材内容不能假称已经读到。

画像与图谱由现有服务生成，作为教师诊断线索和措辞参考；不保证由算法分数推断真实能力，不能仅凭它决定课程资格或成绩。本轮保留原画像算法，不把新的课堂互动回答未经定义地写入画像分数。

[llm_provider.py](../backend/app/services/llm_provider.py) 和 [llm_config.py](../backend/app/services/llm_config.py) 统一提供商与请求策略。现有控制包括并发入口、聊天优先于分析、提供商侧重试与退避、等待模型前结束不必要的只读数据库事务。稳定前缀和有界上下文可减少重复传输，但 API 供应商延迟仍会影响体验。

队列现有默认上限为 12 个执行中请求、128 个等待者、等待 25 秒；满载或超时返回可识别的 503，不无限排队。两组在等待模型前释放事务连接，排队请求在实际外部调用前用短事务重新检查课堂开关。40 人模拟的具体证据见开发文档，不能等同于供应商容量保证。

学生聊天接口将排队、网络和代理故障转换成简短提示，保留课堂关闭的状态刷新。浏览器不会自动重发聊天 POST：没有收到响应不等于模型未执行，盲目重试可能重复计费和记录。

尚不能宣称已解决全校并发：限流在进程内；新增多个后端 worker 不会自动共享队列。完整聊天请求幂等、真实模型排队体验仍需专项核验；研究事件的幂等不能代替模型调用幂等。没有接入即用的 SSE 保证或厂商服务等级承诺。

## 4. 学生代码如何影响画面

Python 在浏览器 Pyodide Worker 中执行，主线程负责游戏状态校验和显示。后端保存个人代码和过程证据，不在服务器上为每个学生逐帧计算游戏。学生仍须运行当前代码；仅在编辑器改字不会自动替换正在运行的版本。

解构组由七个基础函数加已启用的创意函数组织运行。常规 AI 组提供更直接的整段 Python 编辑与可视化，但仍须满足运行接口；自由编辑不等于无限系统权限。两条路径的 UI 与诊断规则不同，正式比较需另行冻结共同任务和评价标准。

创意运行器的公开事件是 `start`、`key`、`before_move`、`move`、`eat`、`loop`、`end`。可用的顶层状态包括 `snake`、`direction`、`food`、`score`、`game_over`、`interval`、`objects`、`timers`。对象、计时器和可视化能力的细则以 [snakeCreativeFunctions.ts](../frontend/data/snakeCreativeFunctions.ts) 与 [creativeCapabilities.ts](../frontend/data/creativeCapabilities.ts) 为准；不要在文档另维护一份会漂移的完整 API。

例如 `state["bomb_time"]` 不是任意可添加的顶层字段，需要使用运行器支持的计时器或对象数据。字面量非法顶层写入、未知事件名等在静态检查中尽早反馈；不能因为样例分支没有执行就宣称所有分支通过。

Worker 超时隔离、受限 Python 能力、状态结构校验和输出限额共同约束代码。创意异常按卡隔离，不能拖死整个界面；`print` 用于受限调试输出，不是开放系统终端。浏览器中的测试不能成为对学生绝对保密的评测材料；真正不应下发的教师蓝图和研究信息必须由 API 权限保护。

运行器区分首次加载与代码执行：初始化失败时销毁保存了失败 Promise 的 Worker，下次由学生运行时重建；普通 Python 错误保留已加载的运行环境。5 秒执行计时从运行开始算，不把首次下载算成学生代码超时。初始化失败恢复已有模拟 Worker 回归，真实机房断网/恢复仍需核验。

## 5. 数据：恢复现场和研究历史不是同一件事

学生共享数据库，但每份工作区按用户和任务隔离；这不要求给每个人建一个物理数据库。前端缓存同样需要用户与任务作用域，切换账号不能继承另一人的卡片或代码。

| 数据层 | 主要记录 | 作用 |
| --- | --- | --- |
| 当前工作区 | `research_task_submissions` | 保存最新状态、恢复刷新后的编辑现场；不是完整过程历史 |
| 产物与版本 | `stage_artifacts`、`artifact_versions` | 稳定标识卡片/流程/代码及其不同内容版本 |
| 行为及关联 | `stage_events`、`stage_event_artifacts`、`scaffold_events` | 记录运行、修改、求助和对应产物版本 |
| 固定任务依据 | `project_blueprint_versions` | 首次绑定冻结版本，后续发布不静默改变在做任务的条件 |
| 教师与测量 | 教师点评、前后测轮次与回答、课堂互动记录 | 为过程解释与独立测量保留原始证据，互不冒充 |
| 课次与准备 | `classroom_lesson_plans`、`preparation_records` | 冻结本课任务/知识目标；分开保存准备区代码、运行与对话 |
| 文件与本地作品 | `classroom_materials`、`classroom_material_receipts` | 发布时任务/脚本快照；按学生绑定下载、提交和原文件哈希 |

课堂小问答复用前后测的 React 逐题组件，不复用前后测业务数据。`classroom_question_sets` 保存不可变题组；发布至某课次时在 `classroom_publications.question` 冻结 `kind=set/title/set_id/questions`，旧单题 JSON 继续读取。新答卷使用 `classroom_responses.answers` 和 `started_at`，旧 `answer` 字段保留。整组校验、跨班授权和关闭检查后一次事务保存；共享行锁允许同班并发提交，唯一约束阻止重复答卷。题目修改另存新版本，不追改发布快照。问答接口不调用模型、不自动评分、不更新画像。

[research_event_service.py](../backend/app/services/research_event_service.py) 负责事件和版本，[research_task_service.py](../backend/app/services/research_task_service.py) 负责工作区。产物使用稳定 ID，不以数组位置代替身份；相同内容可复用版本，但重复运行仍产生不同测试事件。保存失败不得展示虚假的“已完成”。

事件请求的幂等按用户和任务限定：同一请求重放不重复记录，不同内容复用同一键应拒绝。最终提交需要与有效测试证据对应；历史迁移记录继续可读，不意味着恢复已撤下的迁移界面。

求助、模型生成、服务端保存、学生实际阅读和采纳是不同事实。已生成回复不能证明学生已读；`adopted = null` 表示未知，不当作拒绝。缺失的早期时间、模型版本或错误详情不能靠整理历史补造。

新阶段事件的 `detail.lesson` 由服务器注入，客户端同名字段不可信。新课堂消息的 `analysis.lesson` 保留同一关联；助手记录中的 `analysis_source.message_id` 指向被分析的学生消息，不能误把 AI 生成文本的知识点算成学生已经掌握。目标知识点已可保存，逐课概念命中、原句证据与教师复核报表仍待开发，现有累计图谱不替代该报告。

2026-09-15 增补：新聊天的 `analysis.learningEvidence` 保存当轮浏览器编辑器快照及 SHA-256，AI 回复保存明确 `response_to` 与服务器生成耗时；不补造历史快照。观察确认、修改、删除记录 `structure_change`，产物内容保存 `provenance`、学生补充和已知 AI 草稿来源。删除使用版本中的删除标记，不物理移除历史版本；原工作区仍保存当前卡片。来源属于交互记录，不证明独立创作或掌握。

## 6. 教师接口、账号与课堂开关

已有管理功能包括学生详情、教师点评、密码重置、前后测轮次和研究数据导出。新课堂控制模块将课次、短问题和学生回答单独建模，与正式前后测量表区分；本轮开发与验证状态必须以开发文档为准。

注册使用姓名、学号、自设密码，性别可选。数据库只保存密码哈希；教师不能查到学生原密码，忘记密码由有权限的教师重置。哈希、令牌和管理密钥不得作为研究数据导出。

学生使用 JWT 身份，后端核验账号与资源归属；管理端使用真正的管理员身份校验，不能只靠前端隐藏按钮。题本发布后保存版本，变更应形成新版本，不能覆写已经作答学生所见的题目。

发布按教师指定的班级作用。首次进入教师班级页时幂等创建/复用班级容器，不要求开课，不新发任务。空安排不能通过旧任务 UUID 绕过任务级发布权限；历史已发布网页任务仍按原绑定访问，学生登录和 active-task 不自动挑选旧公共任务。当前工作台的 Python、保存与 AI 不再受课堂状态阻断；AI 仍受身份、具体任务 AI 权限及测评限制约束。任务可单独开放或撤回，不删除历史收件；撤回不影响已下载到本机的文件或 SFLS。

`classroom_sessions` 当前作为班级工作容器（不再直接代表一课），旧课次及 `classroom_control_events` 的历史开关记录保留。当前容器始终可用，教师用任务发布/撤回控制内容，旧上下课状态 API 返回 410。`classroom_publications` 冻结每次发布的题目与教师来源备注，`classroom_responses` 保存用户 ID、原始答案、当时班级/组别与提交时间。学生回答共享行锁，教师关闭使用排他锁；同一学生和发布记录唯一，重放不会覆盖原答卷。发布只证明教师发布，不证明学生已读；可选题 `null` 不算零分，也不触发画像更新。

账号增加 `auth_version`，学生和管理员 JWT 均携带版本；重置密码递增版本，使旧登录令牌失效。旧账号默认版本为 0，不覆盖密码或原工作区。学生端不再有上下课遮罩，未同步草稿按用户和任务暂存；不能承诺关闭浏览器时网络请求一定送达。新增 `classroom_notices` 独立短期存储通知正文，按认证班级读取、不进研究导出。撤回/替换清空正文，到期立即停止返回、每分钟后台清空；仅保留 ID/班级/创建人/时间元数据用于重试防重放。通知不等于已读，不进入画像和 AI 提示词。

公开学生登录、两种注册和教师登录共用有界密码计算队列：每进程 2 个工作线程、最多 64 个等待请求、25 秒等待上限，超限返回简短的 503 提示。bcrypt 算法与成本不变，计算移出 API 事件循环；请求取消也不会提前释放仍在计算的名额。等待前释放只读 SQL 事务，计算后重新读取密码哈希、令牌版本和启用状态，教师登录还核对角色。注册提交后的密码重置也不能让旧请求获得新版本令牌。

密码队列独立于模型队列，增加进程会同时扩大二者，不能视为全局限流。需管理员权限的批量重置和账号初始化暂未改为异步密码工作，不宜在课堂集中操作；本机响应测试不能代替服务器并发压测。

## 7. 导出与性能

当前教师入口只有班级选择和完整下载，身份/图谱选项折叠，旧分项导出 API 不删除。`assessment_analysis.py` 在同一 SQL 只读快照生成 `assessment_items.csv/jsonl`，按 25 份答卷分批展开，保留逐题原值、标签、缺失/跳题状态与测量版本；不赋分，不生成未提交答卷。包中“分析说明.md”说明关联/时区/去重/隐私，“数据字典.csv”与 manifest 描述字段和外键。新明细计入导出容量限制。

学生发卷状态使用轻量认证接口 `/api/assessments/status`，ORM 只载入 id/revision，前台 6–9 秒错峰、隐藏暂停、错误退避、单请求在途；仅变化时下载完整题目并全页进入。同卷不重置答题组件。已提交判定仍按 user_id + round_id，班级和答卷隔离由服务端执行，不以客户端缓存代替权限检查。

[research_package.py](../backend/app/services/research_package.py) 从允许清单导出 35 张 SQL 表（原 30 表加共同帮助、练习审核和项目回顾三表）、CSV/JSONL、图谱快照、教材资料和字段说明，附清单、行数与摘要哈希。课堂答案与题目、课次和教师标识保留关联；按当前班级/组别筛选学生时，补入其历史答案、准备记录、资料收取和课堂证据引用的课次。身份字段单独控制；即便不导出姓名，学生自由文本仍可能包含个人信息，不能称为完全匿名数据。上传原件位于 `originals/<表名>/<UUID>.bin`，实际文件名和 SHA-256 在对应表；二进制不重复编码进 CSV/JSONL。

SQL 导出使用一致性只读事务，Neo4j 是另一次读取，不能声称跨库原子快照；知识图谱当前快照也不等于完整变更历史。导出采取分批读取、临时文件、大小和时间限制，并限制同时导出数量，以免占满普通教学请求的内存与连接。

研究包新增 `learning_process.csv/jsonl`，在同一 SQL 快照的 200 行批次中生成紧凑索引，不重复大段作品文本。使用 source_table/source_id 回查原始表，student user_id、课次 session_id、task_id、at 用于关联；消息表的聊天会话 ID 不冒充课次 ID。response_to 只来自明确记录，adopted/mastery 保持未知。`reply_generation_ms` 是服务器生成回复的耗时，不是浏览器完整等待或学生有效学习时长。索引计入原 128 MiB 限制，原 30 张表继续完整导出。

### 传输、服务端和学生电脑分别处理

两端镜像在构建时预生成公共 JS/CSS/JSON/HTML 的 gzip 文件，学生端额外处理 WASM；ZIP 不再重复压缩。原文件保留，不支持 gzip 的客户端仍可使用。外层静态代理明确使用 HTTP/1.1，避免内层 `gzip_static` 因代理请求版本而失效。这里压缩的是公共资源，不共享缓存学生代码、回答或登录信息。[Nginx 官方说明](https://nginx.org/en/docs/http/ngx_http_gzip_static_module.html)

只有内容哈希资源使用长期不可变缓存；HTML 和当前未带版本目录的 `/pyodide/` 使用 `no-cache` 重验证，ETag 一致可复用内容，不是每次重新下载。缺失 WASM 返回 404，不返回 SPA 的 HTML。本地预览也遵循这一缓存区分，但生产预压缩依赖重建前端镜像，不能把本机预览当部署验证。

Compose 已用 Neo4j 5 配置名显式设置：初始堆 512 MiB、最大堆 1 GiB、page cache 256 MiB，可分别用 `NEO4J_HEAP_INITIAL_SIZE`、`NEO4J_HEAP_MAX_SIZE`、`NEO4J_PAGECACHE_SIZE` 覆盖。这不是容器总内存上限，还须给 JVM 原生内存、PostgreSQL、API、操作系统留空间。正式负载可在足够内存下将初始堆与最大堆设为一致，减少堆扩容影响。[Neo4j 内存说明](https://neo4j.com/docs/operations-manual/current/performance/memory-configuration/)

部署建议是待压测的工程起点，不是已验证容量：

| 条件 | 建议与边界 |
| --- | --- |
| 预算受限 | 2–4 vCPU、4 GB 内存、SSD，可作为一班试运行候选；包含 Neo4j 时内存余量有限 |
| 更有余量 | 4 vCPU、8 GB 内存作为优先候选；仍不能解决供应商限流或机房慢网 |
| 后端进程 | 先用 1 个异步 worker；当前模型队列按进程隔离，不用加进程假装全局限流已解决 |
| 课堂前准备 | 提前打开机房浏览器，加载编辑器并实际运行一次 Python，验证浏览器缓存和兼容性 |
| 必测指标 | 全班集中登录、保存、提问的 p95 延迟与错误率，模型等待时间、数据库连接占用和 RSS 峰值 |

本机核心 WASM 由 10,104,029 字节压为 3,169,854 字节，减少约 69%；这不等于整站快 69%。按当前五个 Pyodide 文件估算，40 台全冷浏览器合计仍约需 232 MB 传输；若共享出口仅 20 Mbps，理想传输下限就约 93 秒，尚未算界面资源、协议开销和初始化。因此带宽与预热应和内存一起规划。上述数字是资源测量与算术估计，不是 40 台真实设备测速；当前未承诺某个人数“绝不卡”。

## 8. 本地 Pi 任务包与逐课证据

教师在课堂页填写任务和支持要求，发布时冻结文本及安装脚本；学生下载时注入本人 ID、课次资料 ID 和下载记录 ID。Mac/Windows 包只含配置与脚本，不含主密钥。首次脚本运行在本文件夹 `.runtime` 中安装固定 Node 22.23.2、uv 0.8.22、Python 3.12.11 与 Pi 0.85.1；Node/uv 下载有固定 SHA-256，npm 使用完整性校验和 Pi 发布包的依赖锁。没有全局 npm 安装、sudo 或系统安全策略修改。Windows 限 x64，学校禁脚本时需教师处理，不绕过限制。

Pi 当前官方包是 `@earendil-works/pi-coding-agent`，其 Node 要求、Windows PowerShell 工具及会话目录参数依据 [官方说明](https://github.com/badlogic/pi-mono/tree/main/packages/coding-agent)、[Windows 文档](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/windows.md) 核对；Node 校验来自 [官方清单](https://nodejs.org/dist/v22.23.2/SHASUMS256.txt)，uv 来自 [固定版本发布](https://github.com/astral-sh/uv/releases/tag/0.8.22)。不要把旧 `@mariozechner` 包名或最新版浮动安装写回脚本。实际 Mac 环境安装检查通过；Windows、Intel Mac、学校代理与桌面游戏依赖尚待实机验证。

学生用 `/login` 输入教师另发的独立密钥，保存在 `.runtime/pi-user`，不打入回收包。平台尚未实现每学生限额代理码。Pi 有本地工具权限，AGENTS.md 的目录约定不是安全沙箱；仅在学校允许的实验账户启动。关闭网页课堂不会停止本地 Pi。脚本不自动启用第三方扩展，不收集任务目录外的文件。

回收仅打包 `project` 中的允许类型文件、`evidence` 会话/启动记录及清单，跳过运行环境、隐藏目录和链接。下载时间是服务端开始发送，安装/启动/退出时间是可改写的本地报告，上传时间是服务端接收；不能混为实际专注时长。对话及工具编辑可作过程线索，但不是不可篡改的完整文件版本系统。主密钥不随生成包分发；文件内的隐私和手工粘贴密钥仍需人工检查，正则拦截不保证覆盖所有供应商密钥格式。

文件私有存入 PostgreSQL `bytea`，列表默认不加载内容，单文件 10 MiB；ZIP 最多 500 项、展开 30 MiB，拒绝路径穿越、符号链接、重复/加密文件和常见密钥文件。平台只检查和保存，不解压到服务器、更不执行作品。每个班级容器最多同时开放 20 份资料，每学生每份最多 30 次下载、20 次提交；幂等重传不新增记录。完整研究包保持 128 MiB 总上限，超限明确报错，可分班、排除原件后导出结构化索引并逐件下载原件。大规模长期存储后应迁到私有对象存储，而非扩大接口无界限接收。

逐课查看只读取带可信课次标识的准备记录、课堂消息和事件，每页 50 条，可按学生筛选；无额外模型调用。学生原话、编辑器快照和 AI 提供内容分栏，`literal-mention/v1` 只匹配教师知识点的同名词，不是语义编码或掌握度。旧记录缺课次时不按时间猜归属。现有 Neo4j 仍为累计图谱，尚不是逐课历史图谱，画像算法不变。

教师默认“完整过程”合并上述三类记录的时间索引后分页，再按类型批量读取；事件通过一次关联查询带出产物前后版本，核对学生、任务及版本所属产物。不逐条查询，不定时调用模型。问卷管理另提供只读精简背景模板，教师加载后仅打开未保存草稿，既有发布/冻结规则不变。

学生限额代理码、逐课语义编码与历史图谱、任意新游戏的生成画布、后台按学生执行完整工程、多智能体规划，以及具有正式效度证据的动态画像与支架渐隐，都不能写成现有实现。讨论保留在教学设计和开发待办，不再为每个想法创建独立“最新架构”文档。

## 10. 共同帮助控制器：common-support/v1

新增 [common_support.py](../backend/app/services/common_support.py) 负责状态转移、帮助类型、教材候选与固定理解检查；[learning_support.py](../backend/app/api/endpoints/learning_support.py) 负责权限、幂等、模型调用和证据；[SupportTools.tsx](../frontend/components/SupportTools.tsx) 在通用助手入口复用，功能卡使用针对思路讨论的两个按钮，共用后端协议。不增加自主 Agent、向量数据库、学生容器或额外分析模型。

已发布课次的 `/api/chat` 提前转入共同控制器，不再执行旧“情绪/意图 → 掌握度增减”逻辑；准备区对话也复用控制器。未绑定已发布课次的旧聊天兼容分支仍存在，不能声称所有历史/API 入口都已迁移。新版不根据旧画像选择帮助等级，旧 Neo4j 与历史展示未删除，完整视觉隔离尚待完成。

请求链为：JWT 身份与当前课次/任务/AI 开关复核 → 按本人作用域恢复状态 → 预留 pending 记录 → 释放 SQL 事务 → 规则回应或一次模型调用 → 保存回复和证据。作用域由服务器课次、任务、学生与前端阶段/焦点共同确定；入口名称不进入状态键，准备区不能藉入口名增加权限。焦点是客户端交互情境，不是能力鉴定或防作弊边界。

PostgreSQL 新增 `learning_support_turns` 和 `learning_practice_reviews`，通过现有模型建表机制增量创建，不改旧列、不清理教学数据。同一用户的短事务 advisory lock 与 `(user_id, request_id)` 唯一约束防重复预留；同一内容重放返回已存结果，不重复模型调用；同键不同内容返回 409。等待不占 SQL 连接，不同学生可并行。失败保留 failed，处理中的重放返回 409；异常取消可能遗留 pending，150 秒后允许新请求，不把它当已送达。仍使用进程内有界模型队列，未进行真实整班吞吐验收。

每条 ledger 保存请求、代码与 SHA-256、教材来源/规范 ID/版本、策略版本、状态前后与触发原因、生成耗时和回复；模型回复另保存服务端任务快照、模型名称、token 预算和 prompt 哈希。`requested_level` / `applied_level` 表示策略分配，不是对模型实际代码长度的自动审计；概念/思路帮助没有“已提供实现等级”的结论。`answered` 只说明服务器生成并保存，不证明客户端阅读、采纳或掌握。

普通课堂与功能讨论同时写兼容 `chat_messages`，携带 `commonSupportId`、课次和明确回复关联；准备区原记录仍保存。`learning_process.csv/jsonl` 优先索引共同 ledger，排除这些镜像的重复计数，原始表仍完整保留。教师“本课学习过程”可读原话、代码、AI 回复与教材候选；原始结果未知就保持未知。导出无需新模型，新增两表同样进入只读快照和容量限制。

教师审核接口位于 `/api/learning-support/practice-templates`，由管理员权限保护；审核需匹配内容哈希。当前两份固定草稿审核后全局向两组开放，停止仅影响新发题，已经发出的题目与答案快照保留。每次发题冻结模板、答案、判据、审核人/时间；答题、看解释与退出必须对应本人同一作用域的题目实例。正确只指该题，不自动调整画像或帮助等级。

`GET /api/learning-support/evidence-graph` 是教师专用、最多最近 500 条的候选关联数据接口（超出返回 truncated），不是新的掌握度图谱。节点使用教材规范 ID 和摘要哈希，边回指交互原文；没有将模型自由文本当作新知识节点，没有新增语义编码。当前前端可读候选文本，尚未提供完整图谱可视化和教师编码工作台。

功能卡讨论继续复用共同控制器，但使用 `idea_hint`（具体情境提示）和 `organize`（整理已表达的思路）动作。动作随原消息持久化，快捷求助不算学生实现思路；组织后的 `steps` 必须由学生明确采用和修改。观察/拆功能界面不再请求旧 `function-coverage` API，旧接口与历史数据保留兼容，不以七函数覆盖率为学生完成标准。流程到编程的对照弹窗仅使用公开函数名称，不下发隐藏蓝图答案，不改写学生卡片。

`MockProvider` 区分共同课堂对话与旧分析请求；对话返回带“离线演示”的文本，分析仍保留 JSON 契约。离线整理明确说明不可用，不伪造基于对话的总结。前端对历史内部分析 JSON 只做显示降级，原始研究记录不删除。

## 11. 项目回顾：题本、冻结作品与证据隔离

[project_review.py](../backend/app/api/endpoints/project_review.py) 提供学生 `/api/project-review` 与教师 `/api/admin/project-review`；[ProjectReviewGate.tsx](../frontend/components/ProjectReviewGate.tsx) 位于正常课堂入口之前，[ProjectReviewPanel.tsx](../admin-frontend/src/components/ProjectReviewPanel.tsx) 复用课堂管理页。没有新 Agent、模型调用、后台代码执行容器或教学端口。

- `project_review_rounds` 保存固定题本/判据、版本哈希、教师、所选课次以及草稿/开放/结束/公布状态。建立草稿或读取判据不等于开放。开放需精确题本哈希；公布需本轮已结束及教师确认两个班均已结束。
- `project_review_responses` 按轮次与学生唯一，固定当时班级/组别、课次/任务，保留冻结代码与哈希、首答、运行预期、最新草稿、提交时间和可为空的人工评分。开放时冻结参与名单，仅包括所选已启动课次中有对应任务的在册活跃学生；不自动把迟到注册或后来转班者加入，教师需另行安排。
- `project_review_events` 保留开放、开始、各次保存前后版本、首答/预期、运行、提交、结束、人工评分前后和公布。事件有本人、操作人及幂等请求 ID；独立研究表进入现有 ZIP CSV/JSONL 导出，当前不并入课堂过程索引。按学生筛选时补入被引用的历史课次和教师标识。

点击开始仅从本人所分配任务的已存 `ResearchTaskSubmission` 冻结代码，包含 main.py、基础卡和创意卡代码；不采用客户端提交的“旧版本”，不修改原作品。最多 60 个代码片段和 200,000 字符，超限明确拒绝、不静默截断。草稿显式保存，另有按答卷 ID 隔离的本机恢复；服务端修订号防旧页覆盖，同请求重试不重复记录。提交不要求函数测试通过，提交后只读并继续保持 AI 暂停。

第 2 题首答和第 3 题运行前预期单独锁定；未保存它们不能上报本轮运行。第三题懒加载原浏览器 Python 运行器，暂停并卸载正常课堂运行区，避免两个预览争用 Worker；仅装配冻结代码，但原运行器可能补足缺失能力，因此界面和快照明确提示不是独立实现证明。记录最后一步前后长度、浏览器观察时间及少量输出，标记 `length_source=browser_runner/student_report`、`scenario_source=student_selected` 和 `verified_by_server=false`。学生选择情境/输入结论不能被当作服务器判真。运行引用校验本人、本轮和情境，单轮最多 100 条记录，每条最多 30 行/每行 1,000 字；不持续上传逐帧状态。

[project_review_guard.py](../backend/app/core/project_review_guard.py) 在已认证学生的学习 API 入口检查暂停标志，保留身份、课堂状态、问卷和回顾接口；教师权限仍由原鉴权保护。普通聊天、准备区、旧历史及支持入口均被拦截；模型队列出队前再次检查，回复发送前再检查。若请求期间曾开放回顾，即使很快结束，该在途回复仍不下发。客户端还有请求代际校验和小精灵提问禁用，不能只靠 UI 隐藏实现权限。已发送的字节无法撤回，外部 AI/第二设备不受控制；`answered` 的旧 ledger 含义仍只是服务器生成，不能据此声称学生看过被拦截的回复。

学生状态在可见页面每 3 秒刷新，隐藏时停止定时查询，聚焦即查；轻量 `status_only=true` 只选取状态/修订等字段，不读取或传输冻结代码、题本、评分和答案，状态变化才获取完整答卷。单次请求 15 秒超时，不并发叠加。无模型调用，代码运行在学生浏览器，状态检查用短 SQL 会话，不把连接持有到模型等待结束。仍增加了数据库查询负载，尚未用机房整班实测，不能承诺特定并发容量。

教师手工录入 3/3/4 分和备注，没有自动评分；未评分为 `null`，已公布后评分只读。答案/判据/评分在公布前不进入学生响应。教师结束按整轮释放，不自动替学生提交，未交草稿保留。三张新表通过现有增量模型建表机制创建；本轮只应用到隔离测试库，教学库上线前必须备份并核对增量启动流程，不得重建数据库。
