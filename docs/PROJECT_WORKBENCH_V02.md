# CogniSync v0.2：项目解构任务工作区

## 本版本目标

v0.2 开始把现有的“代码练习页面”逐步改造成单页项目解构工作台。学生不需要在多个页面之间来回跳转；完整项目演示、后续解构画布、代码区、过程记录和 AI 助手都将在同一工作区中以面板或浮动工具的方式协同。

当前版本已经完成第一个可讨论的项目工厂原型：以“运行与观察”为入口，把完整项目、低输入观察记录、解构阶段和原有编码区组织在一个页面内。

## 已实现

- 在学生端“项目工坊”中接入项目工厂顶栏和五阶段轨道：运行与观察、功能拆解、关系建模、实现规划、编码验证。
- 首次进入默认显示“运行与观察”，不再直接把 Python 编辑器作为项目工坊首页。
- 完整项目入口移到项目工厂顶栏和观察任务卡，不再与页面右下角操作区重叠。
- 演示以居中项目查看器打开，限制在浏览器安全区域内；关闭后回到原工作位置，不发生页面跳转。
- 贪吃蛇为真实可运行状态，不是循环装饰动画。
- 支持方向键、WASD 和屏幕方向键。
- 支持开始、暂停、重置、计分、食物增长、边界碰撞和自身碰撞。
- 碰撞后显示与项目解构相关的观察提示。
- 观察阶段提供 6 张结构化现象卡，学生通过点选记录输入、对象、状态、反馈、规则和控制，至少确认 3 项后形成第一份过程证据。
- 当前观察结果暂存到浏览器本地，刷新或切换阶段后仍保留；后续再接入服务器过程证据表。
- 功能拆解、关系建模和实现规划已提供同风格结构预览，真实拖拽与数据持久化尚未接入。
- “编码验证”继续复用原有编辑器、运行终端和任务提交能力。
- 桌面端使用“米白纸面 + 深色实验屏幕 + Signal Lime”视觉体系。
- `720px` 以下自动转为单列，`480px` 以下进一步收紧标题和控制区。
- 组件自身不请求后端，不增加服务器并发压力；游戏循环只在窗口打开、展开且运行时存在。
- 项目查看器使用纯色遮罩，不使用背景模糊；界面不依赖 WebGL、3D 或持续动画。
- 代码编辑器已拆为按需模块：项目工厂首屏资源由约 `585 kB` 降至约 `35 kB`（未压缩构建产物）；只有进入“编码验证”阶段才请求编辑器代码。

## 当前边界

- 贪吃蛇目前是项目工坊中的固定演示，尚未由教师端任务配置决定。后续需要在研究任务中增加 `project_demo_type` 或项目演示配置。
- 当前 6 项观察为固定候选项，本地暂存不能作为正式实验数据；后续需要保存观察事件、确认时间和修订记录。
- 现有 AI 助手仍为项目工坊右侧固定栏，下一步改造成可收起、可拖动的浮动助手，并与演示窗口共享浮动工具层。
- 当前五阶段是前端工作流，后端仍只保存覆盖式代码与最终提交，尚未建立阶段状态、阶段产物和过程快照。
- 三个实验组的项目工厂外壳和差异化工具权限仍需统一设计；项目解构组不能简单复制到另外两组。

## 学校低配置电脑基线

- 默认面向常见 `1366 × 768` 学校电脑，并允许纵向滚动，不以超宽屏为设计前提。
- 禁止把 3D、WebGL、视频背景、持续粒子或高频阴影动画作为核心交互。
- 阶段组件按需渲染；贪吃蛇只在查看器打开且运行时启动定时器。
- Python 环境不得随项目工厂首页加载，只在进入编码验证并主动运行时加载；后续应迁移到 Web Worker，避免阻塞界面。
- 一个页面只保留一个高频运行任务；AI、图谱和代码环境均采用延迟加载。
- 服务器只接收阶段快照和必要日志，不按游戏帧或每次按键上传数据。

## 下一步开发顺序

1. 将观察卡选择从浏览器本地存储接入后端阶段产物与过程快照。
2. 根据观察记录生成候选功能卡，实现合并、命名和修订，而不是预先给出完整答案。
3. 实现低打字负担的关系画布和实现规划：点击、标签、拖拽、连线和句式模板为主。
4. 将 AI 助手改为可拖动、可收起的浮动窗口；AI只做追问、检查和提示，不直接替学生生成完整解构。
5. 为三个实验组提供相同项目工厂外壳，只开放各自实验条件允许的工具。
6. 接入代码快照、运行报错、测试、支架使用和修订记录，并进行 40—50 人并发验证。

## Git 提交原则

v0.2 后续按完整功能分开提交，不把无关历史修改混入同一次提交。建议提交顺序：

1. 完整项目演示窗口。
2. 统一任务阶段与后端数据模型。
3. 观察与问题表征工作区。
4. 功能结构解构画布。
5. 浮动 AI 助手与分级支架。
