# CogniSync 项目工坊开发基线

> 最新产品裁定：2026-09-01。下方“已实现”部分保留旧版能力记录，但后续开发必须以本节为最高优先级；学生仍需为自己命名的每个功能绘制内部流程图，系统关系画布与建构路径规划不再属于目标课堂流程。

## 当前目标

CogniSync 的核心定位是**课堂中的项目解构教学平台**，不是通用在线 IDE，也不是包办学习、创作和最终测评的全流程 Agent 平台。项目解构组的学生从一个可以运行的完整项目出发，先记录可观察现象，再把现象命名为功能并用一句简短模板描述“这个功能怎样发生”。随后学生为每张功能卡绘制内部流程图，但不再绘制功能之间的系统关系或规划模块建构路径；完成单功能流程后进入建构，在 AI 的分级支持下逐个完成七个基础函数、运行测试并观察游戏变化。完成基础贪吃蛇后，学生可以新增创意功能卡。平台在这一教学阶段收集观察、解构、流程、代码、测试和支架交互等过程数据。

教师端继续保存完整项目蓝图、七个基础函数契约、推荐依赖、隐藏测试和分阶段支架规则。学生端不展示复杂的教师路径答案；平台用蓝图做覆盖检查、安全装配和过程诊断。

### 统一产品定位与正式迁移边界

正式迁移不再要求必须在 CogniSync 内部完成。目标实验方案是：学生在平台点击“开始迁移测试并下载”后获得个人化任务包，在统一版本的本地 Pi 编码 Agent 中完成空白迁移任务，最后把代码、自动测试事件和 Pi 会话 JSONL 打包上传回 CogniSync。平台继续承担任务发放、可信起止时间、身份绑定、材料版本、上传校验、最终隐藏测试和研究导出；本地 Agent 承担开放的人智协作编程。

该方案当前是**目标设计，尚未实现**。现有网页“迷宫寻宝”工作台保留为可用原型、任务蓝图和预测试工具，不删除其代码与历史数据，也不能在论文中把未来的本地 Pi 采集链路写成已实现功能。

研究解释必须区分：

- CogniSync 内部数据反映学生在项目解构教学中的观察、功能命名、流程表达、函数建构、创意扩展和 AI 支架使用；
- 本地迁移包数据反映学生在统一开放 Agent 条件下的问题分解、提问、测试、调试、代码修订和 AI 建议审查；
- 迁移结果属于人智协作表现，不等同于无工具条件下的独立编程能力；
- “项目解构组思路更好”必须用行为序列和产物证据检验，不能只用完成速度推断。

## 最新设计裁定

### 学生功能卡

- 学生选择一张自己的观察卡，为观察到的现象命名一个功能；功能名称是主要解构产物。
- 卡内只保留一个“这个功能如何实现”的短输入框，淡化模板为：`先……；当……时……；最后……`。
- 输入框下方提供少量快捷短语，例如“读取按键”“判断条件”“更新坐标”“修改列表”“返回结果”，点击后插入光标位置；不得恢复大段职责、输入、输出、知识点和验证方式表单。
- AI 根据观察卡、功能名称和实现描述检查学生对基础贪吃蛇的功能覆盖，并用简短问题提醒遗漏。最终基础版仍以教师蓝图的七个函数契约和隐藏测试为准，不能只靠模型自由判断。

### 单功能流程图

- 学生逐张选择自己命名的功能卡，用开始、处理、判断、输入/输出和结束等基础图形表达该功能内部如何发生；
- 画布只显示学生自己的观察引用、功能名称和一句实现描述，不恢复功能卡中已经删除的输入、输出、知识点、验证方式或教师契约文本；
- 每张卡至少形成三个节点和两条有向连线并主动确认，确认后的流程作为后续编码与 AI 支架上下文；
- 此阶段不展示或要求功能之间的依赖关系、全局系统关系、拓扑排序或建构路径。

### 七个必做基础函数

1. 建立并重置游戏状态；
2. 根据按键安全更新方向；
3. 根据方向移动蛇身一格；
4. 在空闲网格生成食物；
5. 处理进食、增长和计分；
6. 判断边界和自身碰撞；
7. 按时间间隔组织全部功能。

学生在建构页看到七张基础功能卡，并可通过类似 VS Code 的可折叠侧栏切换。进入建构前需要完成自己功能卡的内部流程图，但不再要求学生绘制功能之间的关系、规划建构路径或完成拓扑排序。教师蓝图中的依赖只用于组织完整运行和诊断，不作为新的学生填写任务或编码锁定条件。

### 建构阶段的 L0—L3

- **L0 看看哪里出问题**：给一小段打印、断言或测试代码，帮助学生定位现象；
- **L1 给我一个关键写法**：给少量相关代码和一句使用提示；
- **L2 帮我补出结构**：给接近完整的函数结构，保留少量关键位置让学生填写；
- **L3 直接完成**：先显示一次明确确认，确认后给出经过教师隐藏测试验证的完整正确函数。

学生把 AI 给出的代码输入或粘贴到编辑器后自行运行，平台显示报错、测试反馈和左侧游戏效果。L3 不静默覆盖编辑器，但也**不要求学生额外填写“原来哪里有问题”或提交解释表单**。研究记录只保存请求等级、实际等级、AI 建议、学生后续代码版本和测试结果。

### 创意功能

- 基础七个函数完成后，学生可自由添加新的功能卡，只填写功能名称和希望出现的效果；
- 每张创意卡拥有独立空白函数模板、连续 AI 对话、运行开关和测试记录；
- 创意内容可以自由描述，但代码必须接入平台提供的安全事件钩子，例如游戏开始、按键、移动前后、吃到食物、每次循环和游戏结束；
- 所有基础函数与已启用创意函数由同一个浏览器端游戏运行器组织，不为每张卡创建互相隔离的假演示；
- 禁止文件访问、网络请求、动态安装依赖和无限循环，保持学校电脑和 40—50 人课堂并发下的稳定性。

### 学生端入口与迁移

- 学生登录后直接进入教师已开放的当前项目，不再先显示画像、雷达图和知识图谱总览页；左上角保留返回和必要的任务切换入口。
- 平台内教学主流程为：`运行观察 → 功能命名与简述 → 单功能流程图 → 七函数建构 → 整体运行与创意扩展`。正式迁移测试作为独立测量阶段，由平台发放统一的本地任务包并回收过程证据。
- 画像、雷达图、知识图谱、支架等级分布和过程证据移到教师端，供教师按学生查看；画像只能调节 AI 表达方式和支持颗粒度，不能决定学生是否可以进入下一阶段。
- “迷宫寻宝”继续复用网格、方向、坐标、碰撞、目标物、计分和循环等结构，作为首批迁移内容；现有网页版本用于原型与预测试，正式实验目标是使用本地 Pi 任务包。坦克大战不作为首批迁移测评。

## 已实现（旧版能力记录，等待按最新裁定收敛）

- 项目解构组使用完整五阶段工作台；AI 项目式组和讲授组仍保留各自界面，不共享项目解构组的关系与路径工具。
- 进入项目工坊后切换为独立全屏工作区，隐藏学生端的通用顶栏与导航；左上角保留“返回”按钮，可随时回到学习首页，不再让两套导航同时占用课堂操作空间。
- 放大项目阶段栏、功能表单、关系卡片、关系检查器、模块标签、代码契约与编辑器字号；低分辨率下优先使用工作区内部滚动，不再通过整体缩小内容来勉强塞进一屏。
- 修复项目工坊未接收用户实验组字段的问题，避免项目解构组错误回退到普通占位流程。
- 功能卡新增所引用运行证据的标识，形成“运行证据—学生观察—功能推测—关系—路径—代码”的追溯链。
- 新增单卡功能流程工作区：
  - 左侧逐张选择学生自己创建的功能卡，中央只处理当前功能内部的实现逻辑；
  - 右侧提供开始、处理、判断、输入输出和结束五类基础图形，并可快速加入该卡已经填写的输入与输出；
  - 流程元素支持拖拽、改名、删除和 `70%—140%` 缩放；从连接点拖线靠近目标图形时，目标四向蓝点浮现并自动吸附到最近入口；每张功能卡分别保存自己的节点、连线和完成状态；
  - 选中流程元素后显示上、右、下、左四个连接点；按住连接点拖动时显示实时预览线，松到另一个元素后形成有向箭头，松在空白处则取消；
  - 学生必须让每张功能卡至少形成基本流程后才能进入项目路径规划，平台不展示教师标准答案。
- 重构系统关系与实现路径工作区：
  - 全局画布只放功能卡，不再把“单个功能内部流程”和“功能之间依赖”混在同一张图里；
  - 学生可拖拽功能卡、移回素材区、缩放画板和恢复布局，遗漏功能不会被系统自动补齐；
  - 选中功能卡后同样显示四向连接点，按住连接点拖到目标卡即可建立有向依赖；进入目标卡吸附区后显示四向蓝点，最近入口放大，松手后保存准确的起止方向；顶部连接模式保留为触控板与键盘操作的备用方式；
  - SVG 连线实时跟随卡片位置，连线方向、卡片位置与删除操作随账号工作台保存；
  - 右侧不再提供点击排序和上下调整按钮，而是把有向图按最长前置链自动划分为 `S1、S2……` 实现阶段；同一阶段内的功能显示为可并行；
  - 拖入画布只表示“纳入本次路径”，不产生顺序。已入画布但没有任何连线的卡片显示为“尚未规划”，需连入路径或移回素材区后才能进入建构；未拖入画布的卡片仍视为学生主动遗漏，允许在综合运行时暴露可观察问题；
  - 点击“按此路径开始建构”时，将连线推导出的阶段顺序写入计划后再切换页面，后续建构严格复用这条路径；
  - 系统检测循环依赖并阻止进入建构，但不会替学生生成唯一标准路线；
  - 明确区分学生负责的函数与平台锁定的绘制、键盘监听、定时运行、模块装配。
- 新增逐模块建构工作区：
  - 左侧明确显示“贪吃蛇 · 当前版本”，包含得分、速度、已实现模块、方向、游戏网格和控制按钮；
  - 点击任一模块卡，只回放截至该卡的累计装配结果；后续模块即使已经完成，也不会提前出现在早期版本中；
  - 右侧严格读取“定路径”中学生放入画布的模块及其实现顺序，不再自行拓扑重排或补入未选择模块；
  - 每个模块回显所引用的观察、输入、输出、知识和验证方式；
  - 模块按前置关系解锁；
  - 代码编辑器只在进入建构阶段时按需加载；
  - “运行模块测试”会在独立 Web Worker 中真实执行当前 Python 函数，并用教师隐藏测试检查输入输出、边界与规则；仅真实通过后才解锁该模块；
  - 测试通过后，左侧立即消费该次 Python 函数的结构化输出，演示初始化、转向、移动、食物、增长计分或碰撞效果；错误代码不会再通过删除 `pass` 或 `TODO` 伪装完成；
  - 修改已验证模块会同时使依赖它的后续模块失效，学生需要按自己的实现路径重新验证；
  - 每个模块保留最近 12 次测试的通过状态、结果码、耗时和时间，随工作区快照同步到账号记录；
  - 模块代码和验证状态先在浏览器即时暂存，停止操作后自动同步到账号记录，不再依赖切换阶段触发保存。
- 新增完整贪吃蛇验收数据：8 条运行记录、7 张观察卡、7 张功能卡、12 条前置关系、7 步建构路径和 6 个学生实现函数；循环、计时、绘制和装配仍由平台负责。
- 不再提供单独的“载入演示”入口。测试账号 `kero / kero` 直接保存一名学生走完整套流程后的真实工作台数据，换浏览器登录后可从后端恢复。
- kero 中的观察卡、功能卡、前置关系、实现顺序和模块代码均可按普通学生方式继续修改；修改后仍按正常流程暂存并同步账号记录。
- 新增账号级 `workspace_data` 保存接口，保存观察、功能、单卡流程、系统关系、实现顺序与模块进度；单次快照限制为 256 KB，避免异常大请求影响课堂并发。
- 工作区采用“本地即时保底 + 数据库防抖同步”：拖动和输入期间不请求服务器，停止操作约 1 秒后只提交一次最新完整快照；离开或隐藏页面时使用 `keepalive` 尝试完成最后一次同步，短暂失败后自动重试。
- 顶部保存状态区分“待保存、保存中、已同步、同步失败但已存本机”，不再把仅写入浏览器缓存误报为已保存。
- 缺失模块会产生不同运行表现：
  - 缺少方向输入时方向键无效；
  - 缺少食物生成时画面没有果实；
  - 缺少增长计分时接触果实不增长或加分；
  - 缺少碰撞判断时蛇可穿过边界；
  - 缺少移动时当前版本不能运行。
- 教师隐藏蓝图仍限定在初始化、方向输入、位置更新、食物生成、增长计分、碰撞判断和循环整合等教材范围内，学生不会接触自由文件系统、多文件项目或任意服务器代码。
- v0.4 教师蓝图后端基础已建立：蓝图草稿使用受约束结构保存项目现象、模块契约、知识责任、同义表达、替代结构、隐藏测试和 L0—L3 策略；发布版本保存内容哈希且不可原地覆盖，后续修改自动创建下一版本。
- 研究任务保存当前发布蓝图，学生首次保存工作区、代码或完成任务时冻结实际使用的蓝图版本；教师后续发布新版不会改变已经开始任务的学生，新进入任务的学生使用最新版本。
- 学生当前任务接口暂时只返回蓝图版本 ID，不下发教师同义表达、标准依赖、隐藏测试或支架内部规则；教师端完整蓝图通过管理员专用接口读取。
- 教师端“教学研究”已增加独立蓝图工作台：左侧读取版本记录与当前学生版本，中间配置项目现象，功能模块页编辑职责、同义表达、输入输出契约、前后条件、前置关系和知识责任；支持保存草稿与发布版本，关闭未保存内容时主动确认。
- 教师蓝图工作台已补充“关系与实现路径”：以轻量 DOM + SVG 呈现全局模块依赖，教师选中模块即可配置必要前置结果；系统实时推导可并行的参考建构层级，并明确它只用于诊断参照，不会变成学生唯一顺序。
- 教师可以配置允许的拆分、合并和替代结构，承认学生对同一项目边界的合理不同表达；前端阻止新增循环依赖，后端发布时再次校验有向无环关系，避免模块互相等待。
- 教师蓝图工作台已补充“测试与建构支架”：按功能模块配置学生函数入口、可视化行为标识，以及示例行为、边界情况和规则约束三类验证证据；输入与预期结果使用 JSON 校验，重复测试标识会在保存前拦截。
- 函数模板只保留函数签名和必要注释，不包含核心实现；隐藏测试仍只保存在管理员蓝图中，学生端获得可观察的通过/失败反馈，不会收到教师测试数据或标准代码。
- 教师蓝图工作台已补充“L0–L3 辅导边界”：按观察、拆功能、理关系、定路径、再建构和迁移反思六阶段分别配置本级目标、AI 允许帮助的范围和代码行数上限；可要求学生在升级前先提供修改、解释或验证证据。
- 学生求助时，服务端读取其提交记录冻结的蓝图版本，把阶段策略与通用 L0–L3 边界同时注入 AI；对话导出额外保留学生请求等级、实际采用等级、蓝图版本、规则来源和代码上限，便于分析支架依赖。
- 教师端已移除旧任务行中的“编辑任务”入口及其代码大表单，避免任务元数据与项目蓝图形成两套并行编辑逻辑；旧字段和更新 API 暂时保留以兼容存量任务，创建任务后统一进入蓝图工作台设计教学内容。

- 浮动项目学习助手已由单次提示框升级为可拖拽的连续对话窗：
  - 始终显示学生当前所在的观察、拆功能、单卡流程、定路径或建构阶段；
  - 学生可以直接描述卡点，也可按需主动请求 L0—L3 递进支架；系统不会根据画像擅自跳级；
  - L0 只澄清情境与目标，L1 提示相关概念，L2 提供局部策略或伪代码，L3 只补足阻塞推进的最小判断、连线或短代码片段；
  - 画像只调节语言具体程度、情感支持和单轮行动颗粒度，不把画像分数解释为能力等级；
  - 每轮支架对话都按“当前学生 + 当前任务”从 PostgreSQL 读取已同步的观察卡、功能卡、单卡流程、实现路径和模块进度，并合并浏览器中尚未同步的最新修改；建构阶段再额外读取当前模块代码与最近测试反馈；
  - 数据库任务快照只读取当前登录学生自己的任务记录，不读取教师隐藏蓝图或其他学生数据；进入模型前会压缩为有限长度摘要，且研究元数据只保留代码长度与指纹，不重复保存完整代码；
  - 点击固定“提示一下”不会被当作学生情绪文本更新画像；只有学生亲自输入的对话才进入情感与画像分析；
  - 每轮对话在 `chat_messages.analysis.scaffoldContext` 中记录任务、阶段、等级、触发方式、画像快照、当前模块、测试反馈、代码长度与指纹，避免重复保存完整代码；
  - 教师端“对话行为数据集”和单个学生对话 CSV 已同步导出上述字段，可用于分析不同画像学生的求助行为和支架依赖。

## v0.4 功能范围

### 教师端：从代码任务管理升级为项目教学设计

教师端把任务名称、说明和实验组投放作为创建时的投放元数据，不再提供旧式代码任务编辑大表单；具体教学内容统一进入以下五个项目设计区域：

1. **项目与现象**：配置完整演示、核心运行现象、自动采集证据和必需/可选行为；
2. **参考蓝图**：用与学生端一致的轻量画布配置模块、接口、前置条件、同义表达、允许的替代结构和隐藏测试；
3. **支架策略**：按阶段配置 L0—L3 内容边界、尝试后升级条件、核心模块限制和教师介入条件；
4. **过程诊断**：查看单个学生的观察、功能、流程、关系、路径、代码测试、支架记录和修订历史；
5. **评价与变式**：配置过程量规，并从原项目复制生成减少支架的局部变式任务。

教师蓝图必须版本化。任务投放后，学生记录始终关联投放时的蓝图版本；教师后续修改不得覆盖已经产生的实验数据。

### 学生端：收敛为一个连续项目界面

- 登录后直接进入当前项目，不先显示画像、雷达图或知识图谱首页；
- 保留完整项目运行与观察卡；功能卡只填写名称和一句实现描述，并提供快捷短语；
- 功能卡之后逐张完成单功能流程图，再进入七个基础函数建构；不再要求学生完成全局关系图和实现路径；
- 建构页左侧持续显示同一个贪吃蛇，右侧以一行或一列功能卡切换当前函数、AI 对话、代码、测试与错误反馈；
- L0—L2 逐级增加测试代码、关键写法和函数结构；L3 经一次确认后给出完整正确函数，不要求额外解释原错误；
- 基础七函数完成后允许新增创意功能卡，通过受控事件钩子与同一游戏运行器组合；
- 现有网页迷宫寻宝作为迁移原型和预测试工具保留；正式实验目标使用平台发放并回收的本地 Pi 任务包，不重复画像首页和复杂路径画布。

### 明确不在 v0.4 首批实现

- 不使用 AI 自动判定整张解构图的对错；
- 不建设实时全班鼠标轨迹监控；
- 不把知识图谱包装成项目结构图；
- 不强制为贪吃蛇制造多条不存在的依赖路径；
- 不记录每次按键、每帧游戏状态或拖拽过程中的连续坐标；
- 不让学生直接填写“非重复性技能、重复性技能”等理论术语。

- 移除系统关系与实现路径画布后不得引入新的图编辑依赖；单功能内部流程图继续复用现有实现，旧路径工作区数据只做兼容读取，不再产生持续拖拽事件。

- AI 提示按学生主动请求或明确诊断事件调用，禁止在每次输入时自动请求。
- 40—50 人同时上课时，服务端重点保护 AI 调用、代码执行、数据库写入和导出任务；普通页面、游戏和关系计算不应形成持续服务器负载。

## 下一轮逐项开发与提交顺序

每一项作为独立能力开发、验证和提交，避免教师端、学生端和数据库同时大改。

1. **工作区入口收敛**：项目解构组登录后直接进入当前项目；画像、雷达图和知识图谱迁入教师单生详情；三组实验条件仍由后端配置隔离；
2. **功能卡简化**：把旧多字段表单改为“引用观察—功能命名—一句实现描述—快捷短语”，接入教师七函数覆盖检查；
3. **保留单功能流程、移除系统路径门槛**：保留 `ProjectMechanismStage`，只移除全局系统关系、实现路径和拓扑锁定，保留旧 `workspace_data`、产物版本和事件的读取兼容；
4. **七函数建构工作区**：右侧固定七张基础功能卡，左侧同一游戏按测试结果实时装配；每张卡统一呈现 AI 对话、代码、运行、错误和隐藏测试反馈；
5. **建构 L0—L3**：按当前函数、代码和测试结果递进提供代码；L3 一次确认后返回完整正确函数，不自动覆盖编辑器、不增加解释表单；
6. **创意功能卡与统一运行器**：允许自由添加功能卡，通过受控事件钩子接入同一贪吃蛇；保存代码版本、启用状态、AI 记录和测试结果；
7. **本地 Pi 迁移任务包**：以现有迷宫蓝图和网页原型为基础，生成学生个人任务包，固定 Pi、模型、提示、工具权限和空白骨架；平台记录发放/启动/提交时间，回收代码、事件与会话 JSONL，并在服务端运行最终隐藏测试；
8. **教师单生过程诊断**：集中展示画像、雷达图、知识图谱、观察/功能卡、代码测试、L0—L3 分布、创意功能和迁移表现；
9. **部署验收**：自托管固定版本 Python 资源，完成 40—50 人并发、断网恢复、低配置电脑和研究导出一致性验证。

### 首批验收标准

- 空白学生能够从观察进入简化功能卡，逐张完成单功能内部流程图，再进入七函数建构；全程不经过系统关系或实现路径画布；
- 七张基础卡都能获得 L0—L3 支架；L3 只有一次确认且给出经过测试的完整函数，不出现额外解释任务；
- 完成或修改任一函数后，左侧同一个游戏立即呈现对应效果，七函数能够组合成完整贪吃蛇；
- 学生可新增、停用和删除创意功能卡，创意函数只能通过允许的钩子运行，异常不会拖垮主循环；
- 教师端能查看学生画像与项目过程数据，学生端不再显示画像/图谱首页；
- 旧学生的流程、路径、版本和事件仍可读取，迁移不得删除历史研究数据；
- `1280 × 720`、`1366 × 768` 与 40—50 人课堂基线保持成立。

## Git 提交原则

按完整能力提交：入口、功能卡、流程收敛、七函数建构、分级支架、创意函数、迷宫迁移和教师诊断分别提交，不混入用户的论文文件或无关材料。
