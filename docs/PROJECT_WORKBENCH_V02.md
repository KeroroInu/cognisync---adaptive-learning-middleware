# CogniSync v0.3：从学生解构到逐模块建构

## 本版本目标

v0.3 将项目解构组的学习链条继续推进为可操作闭环：学生先运行完整项目并形成观察卡，再以观察为证据建立功能卡、前置关系和实现路径，最后只实现自己提出的模块。系统不会自动补齐学生遗漏的功能；遗漏会在综合运行中表现为可观察的问题，促使学生回到解构结果进行修订。

整个过程仍保持在一个项目页面内。教师隐藏蓝图只负责把学生表达映射到安全、有限且不超纲的函数契约，不在学生端直接展示标准功能清单或唯一正确路径。

## 当前学习流程

1. **观察**：运行完整贪吃蛇，系统记录客观运行证据；学生用短句形成至少两张观察卡。
2. **拆功能**：学生引用自己的观察，填写职责、输入、输出，并点选知识和验证方式。
3. **理关系**：学生选择每张功能卡的前置功能，也可保留为起点或并行任务；系统检查循环依赖。
4. **定路径**：系统按学生关系图生成可执行顺序，只给学生已经提出的功能准备安全函数接口。
5. **再建构**：左侧显示逐步装配的贪吃蛇，右侧按学生路径逐个实现模块；前置模块未完成时保持锁定。
6. **综合诊断**：系统只报告可观察异常，例如“方向没有改变”“网格中没有果实”“越过边界仍运行”，不直接告诉学生漏了哪张标准功能卡。

## 已实现

- 项目解构组使用完整五阶段工作台；AI 项目式组和讲授组仍保留各自界面，不共享项目解构组的关系与路径工具。
- 进入项目工坊后切换为独立全屏工作区，隐藏学生端的通用顶栏与导航；左上角保留“返回”按钮，可随时回到学习首页，不再让两套导航同时占用课堂操作空间。
- 放大项目阶段栏、功能表单、关系卡片、关系检查器、模块标签、代码契约与编辑器字号；低分辨率下优先使用工作区内部滚动，不再通过整体缩小内容来勉强塞进一屏。
- 修复项目工坊未接收用户实验组字段的问题，避免项目解构组错误回退到普通占位流程。
- 功能卡新增所引用运行证据的标识，形成“运行证据—学生观察—功能推测—关系—路径—代码”的追溯链。
- 新增关系建模工作区：
  - 直接使用学生自己创建的功能卡；
  - 右侧素材栏同时提供开始、处理、判断、输入输出和结束五类流程图形，以及缩小后的学生功能卡；
  - 流程图形与功能卡均支持拖入画布，并保留点击放入作为触控板操作的备用方式；
  - 流程节点可改名、删除，功能卡可移回素材区，学生可以自行决定哪些功能参与当前系统；
  - “连接节点”模式通过依次点击起点和终点建立箭头，支持功能卡经过判断节点再连接下一功能；
  - 经过流程图形的箭头会转换为后续拓扑排序所需的功能前置关系，避免流程图只成为装饰；
  - 画板提供减号、加号与百分比显示，可在 `70%—140%` 之间缩放，缩放后仍可拖动与放入节点；
  - 使用轻量关系画板自由拖拽功能卡，学生可以按自己的理解组织功能结构；
  - 前置关系以 SVG 连线实时跟随卡片位置，选中功能时突出其输入关系；
  - 右侧检查器负责精确添加或移除前置关系，避免自由连线造成误触；
  - 卡片位置随学生工作台保存，也可一键恢复为便于阅读的默认布局；
  - 支持点选前置依赖；
  - 支持起点与并行任务；
  - 检测循环依赖并阻止进入建构。
- 新增实现路径工作区：
  - 采用拓扑排序生成学生自己的建构顺序；
  - 不自动新增缺失功能；
  - 明确区分学生负责的函数与平台锁定的绘制、键盘监听、定时运行、模块装配。
- 新增逐模块建构工作区：
  - 左侧明确显示“贪吃蛇 · 当前版本”，包含得分、速度、已实现模块、方向、游戏网格和控制按钮；
  - 点击任一模块卡，只回放截至该卡的累计装配结果；后续模块即使已经完成，也不会提前出现在早期版本中；
  - 右侧只显示学生路径中的模块；
  - 每个模块回显所引用的观察、输入、输出、知识和验证方式；
  - 模块按前置关系解锁；
  - 代码编辑器只在进入建构阶段时按需加载；
  - 模块代码和验证状态先在浏览器即时暂存，并在切换阶段时同步到账号记录。
- 新增完整贪吃蛇验收数据：8 条运行记录、7 张观察卡、7 张功能卡、12 条前置关系、7 步建构路径和 6 个学生实现函数；循环、计时、绘制和装配仍由平台负责。
- 不再提供单独的“载入演示”入口。测试账号 `kero / kero` 直接保存一名学生走完整套流程后的真实工作台数据，换浏览器登录后可从后端恢复。
- kero 中的观察卡、功能卡、前置关系、实现顺序和模块代码均可按普通学生方式继续修改；修改后仍按正常流程暂存并同步账号记录。
- 新增账号级 `workspace_data` 保存接口，保存观察、功能、关系、路径与模块进度；单次快照限制为 256 KB，避免异常大请求影响课堂并发。
- 缺失模块会产生不同运行表现：
  - 缺少方向输入时方向键无效；
  - 缺少食物生成时画面没有果实；
  - 缺少增长计分时接触果实不增长或加分；
  - 缺少碰撞判断时蛇可穿过边界；
  - 缺少移动时当前版本不能运行。
- 教师隐藏蓝图仍限定在初始化、方向输入、位置更新、食物生成、增长计分、碰撞判断和循环整合等教材范围内，学生不会接触自由文件系统、多文件项目或任意服务器代码。
- `1280 × 720` 下建构页保持顶栏、游戏、编辑器和模块测试按钮同时可见；窄屏改为区域内滚动或单列，不挤压阶段栏。
- 不使用 3D、WebGL、视频背景或持续粒子效果；贪吃蛇只在学生主动运行时启动一个低频定时器。

## 当前边界

- 当前关系画板允许自由摆放功能卡，但关系的创建与删除仍通过右侧检查器完成；这是为了保留学生的空间表达，同时减少自由连线在触控板和低配置电脑上的误操作。
- 学生表达映射到教师蓝图目前使用本地关键词与运行证据规则。正式实验前需由教师端保存蓝图节点、同义表达和函数契约，并记录映射版本。
- 模块“运行测试”目前是前端原型级接口完整性检查：检测学生是否仍保留 `pass` 或 `TODO`，尚未执行真实 Python 单元测试。正式使用前必须接入受限执行器和教师测试用例。
- 当前已保存账号级工作台快照，但还是“整份覆盖”的原型结构；正式实验前需拆分阶段产物、修订版本和细粒度事件日志，才能可靠分析每一次修改与支架使用。
- 当前左侧画面按“模块已验证”解锁预设行为，还没有直接运行学生 Python 函数。后续真实执行器应返回结构化状态，由同一轻量画面渲染。
- 浮动 AI 助手已有 L0—L3 交互原型，但关系、路径和代码阶段还未接入基于当前产物与测试错误的真实诊断。

## 后端数据最小模型

正式实验时至少需要保存：

- `stage_artifact`：观察卡、功能卡、关系图、路径计划、代码快照、验证结果；
- `artifact_version`：同一产物的修订序号、时间和来源；
- `scaffold_event`：阶段、问题上下文、L0—L3 等级、触发方式、采用与否；
- `runtime_event`：只保存有教学意义的开始、转向、得分、碰撞、测试结果，不保存游戏帧；
- `blueprint_version`：教师蓝图、函数契约、测试用例与映射规则版本。

## 学校低配置电脑与并发基线

- 默认适配 `1366 × 768` 和 `1280 × 720`，允许工作区内部滚动，不以超宽屏为前提。
- 全屏项目工坊只调整现有 DOM 与 CSS 布局，不增加新的运行时依赖、动画引擎或服务端请求。
- 关系与拓扑计算全部在学生浏览器完成；服务器只接收阶段快照和必要事件。
- 关系画板只使用普通 DOM、Pointer Events 和 SVG 路径，不引入流程图或物理布局引擎；拖动过程中不请求服务器。
- 画板缩放只使用浏览器 CSS 变换，流程素材与箭头仍在本地计算，不新增第三方绘图库或服务端负载。
- 游戏状态只在浏览器内运行，不上传每帧和每次坐标变化。
- 代码编辑器按阶段懒加载；Python 执行环境后续应放入 Web Worker，避免阻塞页面。
- AI 提示按学生主动请求或明确诊断事件调用，禁止在每次输入时自动请求。
- 40—50 人同时上课时，服务端重点保护 AI 调用、代码执行、数据库写入和导出任务；普通页面、游戏和关系计算不应形成持续服务器负载。

## 下一步开发顺序

1. 教师端增加“项目蓝图”配置：模块、同义表达、函数契约、前置约束、测试用例和可视化行为。
2. 将现有账号级工作台快照扩展为阶段产物、版本快照和支架事件表，保留每次修订而非只保留最新状态。
3. 接入受限 Python 执行器与真实单元测试，使左侧画面消费学生函数输出。
4. 将 AI 助手接入当前阶段产物、依赖关系和测试错误，实现通用 L0—L3 渐进支架。
5. 实现教师过程看板：查看学生停留阶段、关系循环、测试失败、支架等级和修订情况。
6. 完成 40—50 人并发压测、断网恢复和低配置电脑课堂验证。
