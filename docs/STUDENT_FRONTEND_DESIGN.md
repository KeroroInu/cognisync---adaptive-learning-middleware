# CogniSync 学生端设计基线

更新日期：2026-08-02
适用范围：学生端共享界面、注册与画像卡片、未来三种实验条件的共同视觉外壳。

## 1. 产品方向

CogniSync 的正式定位为“AI 时代的项目解构式编程学习平台”，核心 slogan 为“从解构，到建构。”学生端从“画像仪表盘与功能菜单集合”转向“项目解构学习工作台”。学生从一个可以运行的完整项目出发，通过观察、解构、表达、分步建构、验证和反思形成自己的编程学习路径。

卡牌与雷达图继续承担学习身份、起始画像和过程证据的呈现，但不作为平台的核心叙事。三组共用首页只展示共同信息，不固定展示“解构—建构”阶段；具体学习过程进入班级对应的实验工作区后再呈现，避免向 AI-PBL 组或讲授组提前暴露 PDT 流程。

设计需要同时满足三个目标：

1. 让学生清楚看见从完整项目的解构走向自主建构的学习过程。
2. 让学生感受到项目学习的身份感和过程证据的积累感。
3. 保持教学过程清晰，不让装饰性动效干扰观察、表达、编码和研究数据采集。

### 1.1 品牌与核心路径

- 品牌：`CogniSync`。
- 中文定位：`AI 时代的项目解构式编程学习平台`。
- 核心 slogan：`从解构，到建构。`
- 英文定位：`Project Deconstruction Learning for the AI Era`。
- 英文 slogan：`Deconstruct to understand. Rebuild to create.`

核心学习路径：

> 完整项目 → 观察运行 → 解构功能、数据与关系 → 表达理解 → 分步建构 → 验证整合 → 反思留证

其中，解构与建构是学生必须完成的主体活动；AI 仅在关键节点读取学生的表达、结构图、代码和调试记录，通过追问、提示和局部解释提供支架。

## 2. 参考与转译

主要参考：

- [JIEJOE-WEB-Tutorial / 001-poker-slides](https://github.com/JIEJOE-WEB-Tutorial/001-poker-slides)
- [JIEJOE-WEB-Tutorial](https://github.com/JIEJOE-WEB-Tutorial)

从参考项目提炼的共同设计语言：

- 高反差的底色与前景，而不是低对比玻璃层叠。
- 单一高能强调色，而不是大面积多色渐变。
- 卡片以固定轴点扇形展开，通过层级和旋转形成空间感。
- 动效由悬停、点击、拖拽等明确操作触发，不自动循环。
- 轮廓、线条和几何关系承担识别功能。
- 每个页面只保留一个强视觉焦点。

CogniSync 不复制参考项目的图片素材和完整页面，而是将其交互原则转译为学习场景中的身份卡、项目卡和阶段卡。

## 3. 视觉概念：Learning Terminal & Card Atelier

中文工作名：项目解构工坊。

整体气质是“米白复古计算机＋编辑部式项目档案＋轻量游戏卡牌”。完整项目显示在解构终端中，学生对功能、数据和关系的判断逐步转化为结构表达；画像与过程证据像贴纸或实体卡片一样附着在终端周围。避免传统教育后台的蓝紫渐变，也避免过度儿童化的游戏界面。

### 色彩

浅色模式：

- Paper：`#F3F0E8`，页面底色。
- Card：`#FFFDF7`，主要卡面。
- Ink：`#161713`，文字、边框和侧栏。
- Signal Lime：`#BDF52F`，主行动、完成状态和选中状态。
- Sage：`#DCE4BD`，画像与次级数据卡。
- Oat：`#E8D7B8`，项目卡、成长任务和次级层次。
- Clay：`#C8765E`，仅用于风险、阻塞和错误，不参与普通装饰。
- Amber：`#E7A72D`，进行中和提示状态。

深色模式：

- Canvas：`#11120F`。
- Surface：`#1B1D18`。
- Raised Surface：`#242720`。
- Text：`#F6F3E9`。
- Signal Lime 保持高识别度，但只用于交互焦点；深色模式不重新引入紫色浮光。

配色决策：米白和墨黑构成约 85% 的视觉面积，荧光绿不超过 10%，鼠标浮光、雷达图、知识图谱高亮和按钮统一使用绿色系。紫色不再作为系统级强调色。

### 字体

- 中英文正文优先使用学校电脑本地的 `PingFang SC / Microsoft YaHei / system-ui`。
- 中文主 slogan 使用本地宋体系统栈，形成编辑部式视觉焦点。
- 代码、编号和数据使用 `SFMono-Regular / Consolas / ui-monospace`。
- 生产页面不从 Google Fonts 加载字体，避免学校网络阻断导致首屏等待或字体闪烁。若后续要固定字体，应改为经过子集化的本地 WOFF2。

标题通过字重、大小和留白形成层级，不使用持续流光文字。

### 形状

- 普通数据容器：6–10px 圆角，细墨线边框。
- 学习卡/项目卡：18–22px 圆角，可使用倾斜和堆叠。
- 操作按钮：以胶囊或硬边标签为主，不对所有元素使用相同圆角。
- 阴影偏短、偏硬，表达纸张叠放，而不是漂浮玻璃。

## 4. 卡片体系

### 学生起始卡

注册画像完成后生成。卡片只表达来源明确的起始倾向，不把自我报告包装成能力诊断。

建议字段：

- 昵称或姓名。
- 起始称号。
- 兴趣主题。
- 两项起始倾向。
- 一项成长任务。
- 支架偏好。
- 卡面主题、徽章和编号。

AI 只返回受约束的结构化 JSON；最终卡面由前端模板渲染，不让图像模型直接绘制带文字的整张卡片。

### 项目卡

用于展示贪吃蛇等学习项目，包括项目封面、阶段、当前任务、项目条件和继续入口。项目卡可以与学生卡形成一组可切换的牌组。

### 证据卡

项目结束后根据实际过程证据生成，呈现项目解构、调试、验证和集成等维度。证据卡与起始卡分开，避免把注册画像等同于真实学习表现。

## 5. 动效规则

- 默认界面保持静止。
- 卡牌悬停时允许 2–4° 轻微抬起或展开。
- 点击牌组时，前卡退到末尾，其余卡片沿固定轴点轮替。
- 按钮只在悬停和按下时进行描边、位移或颜色变化。
- 页面进入动画不超过 400ms。
- 编码、量表和长文本阅读区域不使用装饰性动画。
- 必须支持 `prefers-reduced-motion`。

浮光规则：所有 Spotlight/hover glow 使用低透明度橄榄绿 `rgba(142, 169, 68, 0.13–0.14)`，不再按页面分别使用紫、粉、蓝色浮光。

## 5.1 登录场景

登录页采用左右分栏的“项目解构终端开机”场景：

- 左侧保留清晰的学号、密码、登录与注册链接。
- 右侧用 HTML/CSS 构建米白复古电脑，不依赖位图素材。
- 屏幕固定展示贪吃蛇项目，表达学生即将进入真实项目环境。
- 机身下方粘贴起始画像卡、项目卡和下一步卡，连接注册画像与后续项目学习。
- 电脑与贴纸默认静止，仅在鼠标进入整个终端时轻微抬起。
- 整台电脑支持鼠标或触摸拖动，通过受限的 X/Y 轴旋转形成真实 3D 观察；双击恢复默认角度。
- 贪吃蛇沿固定网格路线低速循环，用于表达项目处于可运行状态；开启“减少动态效果”时停止循环。
- 小屏幕改为上下布局；极窄屏缩放终端展示，不影响表单操作。

## 6. 学生端信息层级

当前共享层级：

1. 平台定位、当前项目入口与学生身份卡组。
2. 左侧画像雷达，以及右侧认知、情感、行为三项当前数据。
3. 基于真实过程记录还原的近期变化折线图。
4. 当前项目或当前研究任务。
5. 知识图谱、过程证据、量表、校准和辅助工具。

当前导航结构：

- 学生端不设置常驻左侧栏，页面使用全屏学习工作台。
- 顶部只保留“总览、对话、知识图谱、项目工坊”四个高频入口，作为始终可见的主学习路径。
- “更多”面板收纳校准、证据、量表、主题、语言和退出等低频操作，避免功能消失但不长期占用空间。
- 共用首页不展示任何实验组专属的固定学习阶段；PDT、AI-PBL 与 Lecture 的具体流程只在各自工作区中显示。
- 品牌标识始终可以返回学习首页；深层页面不依赖浏览器后退才能离开。
- 三种实验条件继续共用这一导航外壳，具体可见入口由后端功能配置决定。

## 7. 三组实验界面的共同与差异

所有组必须共用：注册、班级识别、学生卡、视觉外壳、项目素材、代码运行环境、保存反馈和最终测评入口。

条件差异只出现在学习工作区：

- PDT：项目观察、学生解构画布、节点说明、分步实现、系统集成与过程反思。
- AI-PBL：完整项目工作台、普通项目里程碑、自由 AI 支架和在线编辑调试。
- Lecture：教师规定的课程目录、教学示例、顺序练习和在线编辑调试。

三组不分别维护三套前端代码，而由后端返回的 `experienceProfile` 与功能配置决定导航和工作区。

## 8. 研究与数据边界

- 班级决定实验界面，画像只决定卡片和被允许的个性化支架。
- 三组在个性卡出现前完成共同基线测量。
- 卡片文案必须保留数据来源和版本。
- 学生可以确认或修改 AI 生成的称号与描述。
- 不根据注册问卷直接展示“编程能力 90”之类的能力分数。
- 项目完成、测试通过和最终作品质量不能单独等同于真实学习。

## 9. 当前实现阶段

本轮先完成学生端共享视觉系统：

- 全局色彩、字体、边框、背景和交互状态。
- 无常驻侧栏的全屏学习工作台与顶部任务导航。
- 学习首页首屏呈现平台定位、项目入口和画像牌组，保留身份感但不混入统计卡。
- 首页主叙事为“AI 时代的项目解构式编程学习平台 / 从解构，到建构”。
- 首屏下方使用“左侧画像雷达；右侧三项当前数据；右下近期变化折线图”的中性画像概览，不呈现组别专属教学过程。
- 近期变化折线图只使用真实画像快照增量；无历史记录时仅显示当前点并说明数据尚未形成，不虚构趋势。
- 登录、注册、输入框和主按钮的一致样式。
- 登录页的复古项目解构终端、贪吃蛇屏幕与画像贴纸卡。
- 全站残留紫色浮光与渐变统一替换为米白、鼠尾草绿和荧光绿。
- 现有对话、知识图谱、证据和研究页面通过共享样式自动继承新系统。

后续收到用户提供的球星卡网页模板后，再替换学习卡的具体卡面结构，并接入真实的 `studentCard` 数据模型。

## 10. 响应式与学校机房基线

- 优先保证 `1366×768` 与 `1280×720` 的学校常见电脑可完成全部操作，再兼容更宽屏幕与移动端。
- 取消侧栏后，`1280px` 与 `1366px` 首页维持双栏 Hero，让标题和画像牌组在进入系统时同时可见；雷达图与数据概览位于下方独立区域，`1180px` 以下 Hero 改为单列。
- 页面内容按真实高度生成网格行，较矮屏幕由主内容区独立滚动，不压缩或裁切卡片、表格与按钮。
- `820px` 以下顶部导航形成独立横向任务栏；窄屏允许该栏自身横向滚动，不能挤压主工作区或把“更多”按钮推离视口。
- `640px` 以下卡牌缩小并收紧展开角度，三张卡始终留在 Hero 边界内。
- 数据表和代码区允许自身横向滚动，但整个页面不得产生不可控的横向溢出。
- 当前回归检查覆盖学生端 `1366 / 1280 / 390px`，并通过真实 `390px` 设备视口检查顶部操作与页面横向溢出；管理端覆盖 `1366 / 1280 / 860px`。

## 11. 管理端视觉一致性

管理端与学生端共用 Paper、Ink、Signal Lime、Sage、Oat 和 Clay 语义。亮色为默认主题；侧栏、页头、统计卡、表格、导出卡和主要按钮使用相同的纸面、描边与硬阴影规则。管理端可以保留错误、警告、成功等语义色，但不得重新引入紫色渐变或持续浮光。

性能层面避免把 3D、图谱或动画放入全局布局。视觉动效仅由 CSS transform/opacity 或局部 Canvas 驱动，并遵循 `prefers-reduced-motion`；后续开发以 40–50 名学生同时在线为最低并发验收场景，前端大模块按路由拆包、实时请求限频、图谱按需初始化。

## 12. 准实验实施前的功能完善清单

以下能力属于目标平台设计，当前实现程度不一。论文中的教学设计图可以将其作为拟实施机制呈现，但在平台功能图、系统说明和实验材料中必须区分“已实现”与“待完善”，不能把设计构想表述为已经稳定采集的数据。

### 12.1 PDT 解构与建构工作区

- 增加学生项目解构画布，支持功能、数据、规则和模块节点的创建、拖拽、连接与说明。
- 保存学生绘制的模块关系和功能依赖，而不是用自动生成的知识概念图替代项目结构图。
- 将完整项目观察、结构表达、分步建构、整合验证和反思留证组织为可配置任务阶段。
- 教师端能够查看学生解构产物、阶段状态和修改历史，并允许按量规评价或反馈。

### 12.2 分级 AI 支架与渐隐

- 建立 L0 情境澄清、L1 概念提示、L2 策略提示、L3 局部实现四级求助机制。
- 支持教师按实验组、任务、阶段或学生配置可用支架上限，学生端明确显示当前可用层级。
- 支持按任务轮次、学生表现或教师操作调整支架强度，并完整记录调整原因与时间。
- AI 回答采用提示词、输出检测和代码长度限制等多层约束；系统只能表述为降低直接给出完整方案的概率，不能承诺绝对阻断。

### 12.3 过程证据与可追溯性

- 在保存、运行、提交和阶段切换等关键事件生成代码快照，不记录每次按键。
- 保存运行结果、报错摘要、运行时长和调试事件，形成可以还原的调试轨迹。
- AI 提供的代码片段通过受控的“插入编辑器”入口标记来源，并基于后续差异计算修改情况。
- 增加验证结果、学生解释和阶段反思字段，避免仅以最终作品完成度代替真实学习过程。
- 区分平台自动采集证据、学生主动提交证据和教师评价证据，并为每条证据保留来源、时间和任务上下文。

### 12.4 教师端过程诊断与调节

- 展示任务进度、解构产物、分级求助分布、代码版本、运行调试记录和解释反思。
- 支持教师调整任务开放状态、组别支架策略和个别学生的支架上限。
- 将“教师调控中心”落实为任务配置、过程诊断和支架调节功能，不把仅能浏览原始数据的页面包装成自动教学决策系统。
- 修复学生画像校准的前后端持久化、行为日志写入和 Neo4j 图谱真实导出，确保管理端显示与研究导出一致。

### 12.5 并发与性能边界

- 以单班 40–50 人同时进入任务、保存代码、运行项目和请求 AI 为最低验收场景。
- 代码运行尽量保留在学生浏览器端，服务器只接收节流后的关键事件和阶段快照。
- 代码自动保存与过程日志分离：自动保存覆盖当前稿，关键事件才创建历史版本，避免数据量随按键次数膨胀。
- AI 请求设置并发限制、排队、超时、重试和降级提示，避免全班同时提问时压垮模型供应商接口。
- 教师端统计使用分页、聚合查询和按需加载，图谱与大体量过程记录不在首页一次性加载。
