| 优先级 | 代码证据 | 影响与改造方向 |

## 建议新增的课堂流程

教师入口称“课堂互动”，选择班级和课次后只有主要操作：开始上课、发一道题、查看回答、结束课堂。高级信息折叠，题库编辑复用现有题目结构和校验。性别不作为能力推断依据。

```text
教师创建课次 → 开课 → 发布问题 → 学生弹窗作答 → 原始答案入库 → 教师汇总/研究包导出
                  │                                  │
                  └─ 教师结束 → 短暂保存窗口 → 关闭学习权限
```

问题正文和选项首次发布后冻结。再次询问同一道题应产生新的发布实例，关联原题，不能覆盖上一次答案，也不能因为第一次已答而不再出现。同一班级同一时刻只显示一道有效课堂问题。学生看不到他人答案；教师聚合结果与未回答人数不混淆，未回答不是零分。

数据按 `user_id → lesson_id → publication_id → response_id` 关联即可；“每个用户的数据”不需要给每个学生新建一个数据库。复用题目校验及答案呈现，课堂课次、发题实例、回答记录与前后测独立管理，避免把课堂题塞进前后测优先队列。每次发布存教师身份、班级、题目快照/来源、时间；答卷存学生 UUID、班级/组别快照、原始选项值、提交时间。客户端呈现时间只作观测，不宣称防篡改计时。

研究包同时导出问题发布和逐学生逐题原始值，不能只给柱状图。UI 使用一次一道题、大按钮和清晰文字，不要求学生解释选择理由。断线时保留草稿；重试幂等；关闭后不接受新的答案并给出明确提示。

首版可采用仅课堂页面启用的轻量轮询（例如约 3 秒并加抖动），隐藏页面暂停、重新聚焦补查、不重叠请求；轮询只查轻量课堂状态，不读全体答卷/图谱，不调用 AI。50 个活跃页面约产生每秒 17 次轮询请求，这是算术估计，不是已通过压测的容量结论。状态查询需有索引并有界；如实测不满足课堂延迟，再评估事件推送，不提前增加消息平台。

## 下课关闭的是学习权限，不是服务器

状态建议为 `open → closing → closed`。教师点击结束时停止新 AI 请求和新任务操作，通知学生保存；短暂保存窗口只接受本课已有工作区的受限保存，不允许借此调用聊天或创建任意新任务。窗口结束后学习 API 服务端拒绝访问；保留登录、课堂状态查询、教师管理和导出。教师可重新开放，关闭和重开记录操作者与时间。

关闭不能只隐藏按钮，旧令牌和直接请求也要受限；排队中的模型请求在实际发往供应商前再核查，不能下课后继续消耗队列。已经发出的上游请求不保证能撤销收费，应单独说明与测试。前后测是否允许课后继续填，作为独立教师发布状态，不与课堂关闭含混绑定。

已经下载到学生机器的前端程序、代码和本地 Pi 无法远程收回。因此能保证的是服务端资源与平台学习入口关闭，不能承诺停止学生电脑上的一切离线执行。

## 简化身份的待确认方案

学生表单仅姓名、学号，性别用有文字标签的两个选项并允许暂不填写。班级和实验组由教师名单/课堂入口确定，不让学生自行更换研究条件；旧账号 UUID、密码和历史答卷保留。

尚需用户选择：教师批准浏览器绑定，或教师发放个人登录码。只输入公开的姓名和学号不能直接获取旧账号令牌。

设备绑定并不天然等于实名验证：首次申请必须由教师核对名单与当前学生，换机/清除缓存需恢复流程；机房共用机器不能长期自动进入上一位学生账户。下课撤销会话、显式退出、重开课重新确认身份，以及绑定凭据的作用域/有效期/撤销和存储方式都需一起实现。个人登录码则需随机生成、哈希存储、尝试限流和可撤销，不能用学号派生或使用全班共享码充当个人身份。

这属于实质性的认证改动，确认前不删除密码入口、不修改真实学生身份数据。

## 实施拆分和验收

建议四个独立步骤，每步完成后才扩大范围：

1. 抽取共用题目/答案校验和数据呈现，行为不变；确认前后测回归不变。
2. 实现课堂课次、发题、弹窗、回答和导出；不依赖模型、不动画像。
3. 接入服务端课堂权限，覆盖旧令牌、在途请求、保存宽限和教师例外。
4. 在身份方案确认后实现简化入课；保留旧账户恢复与研究主键。

```text
发题 ── 正常/非本班/已关闭/重复发布 ── 弹窗与范围测试
答题 ── 正常/重复请求/不同答案重试/非法选项/关闭竞态 ── API 集成测试
弹窗 ── 编辑中/输入法中/断网/刷新/多标签页 ── 前端与浏览器测试
下课 ── 在途保存/排队 AI/旧令牌直调/教师操作 ── 权限与时序测试
入课 ── 冒用/重名/重学号/换机/共用浏览器/撤销凭据 ── 认证测试
导出 ── 班级过滤/发布版本/重复发题/缺答/身份列关闭 ── 关联与完整性测试
```

关键失败处理：网络失败保留草稿且不显示成功；关闭与答题并发必须有明确落库/拒绝结果；发布换题不把旧答案绑定到新题；过期请求不能重新打开弹窗；课堂关闭不卸载并丢掉最后一次编辑；任何证据写入失败不能生成假完成标记。

初始容量验收建议 50 名模拟学生同时拉取课堂状态、提交单题，叠加真实规模的保存和有限模型请求，记录 P50/P95、错误率、重复行数及连接池占用。模型请求先用有延迟的桩验证队列，再经授权做少量真实供应商测试。独立 `*_test` 数据库运行，不清理真实库。随后在 1280×720 做教师发题到学生弹窗的真实浏览器验收。

## 本轮明确不做

- 不迁移成微服务或多智能体：无法直接解决课堂发题和数据关联需求，反而增加部署负担。
- 不改画像算法、量表计分和研究结论：需另行讨论科学性，原始回答不能自动变成能力标签。
- 不自动生成并发布正式调查题：开题只有调查方向，题本仍待教师定稿。
- 不恢复网页迷宫或开发 Pi 安装包：与本次课堂控制无关。
- 不合并旧目录或更换端口：避免与现有未提交资料混合；执行目录需保持明确。

待确认的认证方式与实施范围未消除前，本架构审查状态为 NEEDS_CONTEXT；不宣称功能已开发、浏览器已验收或并发已通过。
