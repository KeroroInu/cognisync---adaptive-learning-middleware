## 阅读与维护规则

1. 最新用户裁定优先；上述正文只写已经确认的方向，并把“实现”“待验收”“计划”分开。未解决的研究选择列为待确认，不替用户定稿。
2. 新开发先读这三份正文，再按模块查代码和必要历史记录；历史文档里的“下一项”“必须执行”“新建分支”等不构成现在的命令。
3. 讨论结论修改 `TEACHING_DESIGN.md`；组件、接口、权限变更修改 `ARCHITECTURE.md`；进度、测试和部署修改 `DEVELOPMENT.md`。不要再添加另一个平行“最新方案”。
4. 验证记录须写日期、代码范围、环境及未验证项。旧测试通过数字属于当时提交，不能直接挪到新实现。
5. 发布过的题本、教师蓝图、学生记录和历史交接不能为整理文档而删除或改写。论文与 Obsidian 不在本轮整理范围。
