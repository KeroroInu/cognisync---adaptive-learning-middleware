## 3. 本地运行与统一入口

面向用户的统一入口固定为 `http://localhost:8003/`；教师页面为 `/admin`，前后测管理为 `/admin/assessments`。这是项目约定地址，不表示服务当前必然正在运行。新验收开始前检查现有进程，不静默退到 8004/8005。

推荐先做只读核查：

```bash
git status --short
git branch --show-current
docker compose ps
lsof -nP -iTCP:8003 -sTCP:LISTEN
```

若 8003 已有服务，先确认它来自哪里以及是否在使用目标数据库；不能随手杀掉无关进程或启动新的数据卷。数据库连接检查不要把密码、令牌或完整环境文件贴入日志。

### 已有 Compose 方式

[docker-compose.yml](../docker-compose.yml) 的 Nginx 将学生端、管理端和后端统一到 8003。PostgreSQL 和 Neo4j 使用命名卷，数据库端口仅绑定本机。生产配置需真实密钥与备份，不能把仓库示例当作部署安全设置。是否启动、重建或迁移数据库需依任务范围决定。

新预压缩配置需重建学生端、管理端镜像并加载外层代理配置才生效，本轮仅验证，未执行教学部署。服务器候选规格、带宽估算和 Neo4j 配置见[架构说明第 7 节](ARCHITECTURE.md#7-导出与性能)。不要只升内存而忽略全班首次下载 Python 和外部模型的等待。

### 同库本地预览方式

[backend/preview.py](../backend/preview.py) 将两个前端构建目录与正常 API 放在同一个本地服务中，不清空或重建学生工作区，且禁止在 `APP_ENV=production` 下使用。

先在各目录完成构建：

```bash
# frontend/
npm run build

# admin-frontend/
npm run build
```

在确认 8003 可用、现有数据库配置正确后，才从 `backend/` 使用可用虚拟环境运行：

```bash
venv/bin/uvicorn preview:app --host 127.0.0.1 --port 8003
```

预览不带来新的数据库。不能为了绕过连接错误偷偷创建空库；若缺配置，先说明缺什么。独立 Vite 脚本仍存在，仅用于明确需要热更新的开发场景，不应把多个开发端口交给教师当课堂入口。
