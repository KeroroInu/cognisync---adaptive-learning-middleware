# 课堂实验执行基线（2026-09-09）

状态：根据当前讨论整理的执行计划与实现清单，不是已经实施或验证的研究结果。学校课时、样本、分组办法、最终测量题本和评分规程仍需研究者与导师确认。若旧文档与本文件冲突，课堂范围以本文件为准；代码实际状态见 [本轮验收记录](CLASSROOM_ACCEPTANCE_20260909.md)。

## 1. 这次平台负责什么

平台用于高中编程课堂中的人智协同学习、教师观察和过程证据采集。要检验的是：学生是否形成从整体理解问题、分解功能、表达逻辑、检查并修订方案的思路，及其是否有助于后续建构。不能把填了几张卡、画了几张图直接当作“具备解构思维”。

正式条件只保留两个组，两组都有 AI：

| 条件 | 课堂活动 | 应保持一致的条件 |
| --- | --- | --- |
| 项目解构＋AI（`pdt`） | 运行观察 → 命名功能与一句实现描述 → 单功能流程 → 函数建构、测试与扩展 | 教学内容、可用时间、项目目标、设备、模型版本及一般技术支持 |
| 常规 AI 协作（`ai_pbl`） | 在共同项目任务中编写、测试与迭代，不强制完成解构组的卡片和流程活动 | 同上；任务难度与最终评价规程一致 |

解构组的流程和分级支架是教学处理的一部分；当前两组支持策略不是完全相同，不能宣称实验只隔离了“画流程图”一个因素。课堂开始前应冻结两组策略、记录教师指导差异。如果研究要单独归因于解构活动，需另行控制 AI 提示策略，不能在实验后改变解释。

实现缺口：上表是目标安排，当前常规 AI 组仍沿用整文件编辑器，解构组使用七函数共享游戏；旧数据库的活动任务也未统一为共同贪吃蛇项目。正式实验前须统一任务及运行/测试能力，保留是否进行解构活动和相应支架的预定区别。不能把现状称为已经控制好条件的实验。

`lecture` 只保留旧数据兼容，不再分配新学生或新任务。不要把原有账号自动改组。`unassigned` 表示等待教师安排。入课不以旧版画像问卷或 AI 访谈为条件，不补造量表、画像或已完成标记。教师决定何时发布正式测量工具。

网页迷宫迁移模块已退出本轮。下载个人文件包、本地安装 Pi、统一任务与日志采集、提交压缩包仍是后续方案，当前尚无可用的端到端下载回收链路；不能把它当作本次代码已交付项。

## 2. 尽量少打断学生

学生主要操作是玩、写一句发现、命名功能、画内部流程、写或补代码、运行和求助。不要追加“解释原错误”“为何采用 AI”“每次反思”等表格。教师课堂点评在教师端完成。

基础函数提示沿用 L0—L3：定位问题 → 少量关键代码 → 带简短注释和一至两处填空的结构 → 一次确认后的完整当前函数。学生看懂后自行放入编辑器并运行，不自动覆盖其代码。创意函数的能力边界仍由运行器协议决定，不承诺任意 Python 库或任意视觉效果都可实现。

教材资源为用户提供教材第二章的七张核对摘要，按当前功能和问题检索最多三张，并保留来源版本、页码及哈希。不是教材全文，也不能形式化保证模型回复永不超纲。教师需抽查真实问题；不懂状态字典、事件或接口时，先用一句用途说明，不默认学生已经学过。

## 3. 评价与数据如何对应

下面是建议的操作性评价安排，不是已验证量表或正式评分工具。正式收集前须锁定任务、指标、评分锚点和评分者规则。

| 要回答的问题 | 建议依据 | 不宜直接使用的替代指标 |
| --- | --- | --- |
| 编程复杂技能的任务表现怎样 | 共同任务的功能正确性、边界情况、测试与调试、代码理解和修改；最终作品＋少量共同解释/修改任务 | 代码长度、AI 给出的代码量、单纯完成速度 |
| 编程场景中的复杂问题解决表现怎样 | 同一任务中目标与约束识别、分解与方案组织、依据反馈修订、检查结论的行为与作品证据 | 单凭满意度、自信、画像分数或问卷总分 |
| 不同学生怎样与 AI 协作 | 提问—回答—代码修改—运行/失败—再提问的时间关联，及教师观察 | 提问越少就越独立、L3 越多就越差 |

两类表现可以来自同一任务，但应分别给出指标定义，不把“功能通过数”重复计入多个综合分来制造一致性。作品测试反映协作条件下的表现；若要声称学生独立理解，需提供不依赖当轮 AI 代答的共同解释或小修改证据，并控制时间和难度。

一个可试行的顺序是：共同前测任务 → 若干节课堂教学 → 共同后测/迁移任务。前后任务应难度相当、评价标准一致；不能把解构组练习过的同一份代码原样用作比较另一组的最终测验。最终是否采用本地 Pi，不影响先确定任务和评分规程。

研究者尚需完成：选定正式测量工具及授权/适龄条件、核对计分办法；对自编任务与评分规程做教师/专家内容审查及小范围试做；对开放作品/过程编码安排独立双人评分并报告一致性。这里只描述待办，不提供未核验的工具名称、信效度数字或“直接可执行”的保证。

## 4. 每节课怎么收集

课前：确认班级、两组名单、当次课次编号、任务/蓝图与 AI 配置；排除 demo 和验收账号。记录当天实际课时、网络异常、缺勤及额外指导。分组名单与后来调整原因应单独留档，当前用户表不是完整的分组历史。

课中：自动保存已有对话、工作区、卡片/流程版本、测试/求助/确认事件；教师在单生详情记一句可观察事实，必要时补判断或指导，关联事件。可选评分默认收起，只记录研究者已经确定的规程版本、指标、分数和满分，事实作为评分依据；空白代表未评，不是零分。更正以追加记录关联原记录，不能覆盖原评分。

课后：教师端“数据导出 → 课堂研究包”，按班级下载 ZIP 并核对 `manifest.json` 的筛选、行数和文件哈希。保留只读原始包，复制后再编码分析。原始包包含教师材料，不发给学生；对外共享前逐项脱敏。数据库恢复备份另做，研究导出不是运维备份。

## 5. 导出包能给什么

新接口：`GET /api/admin/export/research-package`，仅有效教师管理员登录可用。19 类 SQL 表逐表提供 CSV 和 JSONL，另含图谱快照、教材摘要、字段/外键字典、行数和校验值。

| 分析资料 | 数据来源 | 主要关联 |
| --- | --- | --- |
| 观察、功能、流程、代码及其修订 | `stage_artifacts`、`artifact_versions`、`research_task_submissions.workspace_data` | `user_id`、任务、产物 ID/版本 |
| 测试、求助、阶段确认 | `stage_events`、`stage_event_artifacts` | 事件 ID → 产物版本；计数前按事件去重 |
| AI 对话与支架 | `chat_sessions`、`chat_messages`、`scaffold_events` | 学生、会话、消息、阶段/功能上下文 |
| 课堂事实、指导与可选评分 | `teacher_notes` | 学生 UUID、课次、事件、评分者、规程版本、更正关系 |
| 问卷与系统估计 | `scale_responses`、`scale_templates`、`profile_snapshots`、情感/行为/校准记录 | 学生、时间；保留来源，不混成能力分 |
| 解释教学条件的资料 | 任务、冻结蓝图、入门会话、教材摘要、当前图谱 | 版本、哈希、学生 UUID |

`users.id` 是内部关联主键；`teacher_notes.student_id` 同样存 UUID，不是登录学号。默认不输出结构化姓名、学号和邮箱，但对话、代码、备注可能含个人信息，因此只是减少显式身份字段，不是匿名化。

现有数据缺口必须保留：未保存浏览器草稿无法恢复；没有采集的模型精确版本、网络等待及离开页面时长不能补造；旧量表答卷未存当时题本快照的不能由当前模板反推；图谱是导出时状态，不是完整历史；共享概念边不是某位学生独立构建的证据；`adopted=null` 表示未知而非未采用。前后测开始前应分别保存发布题本和计分规程的不可修改副本。

## 6. 服务器与课堂前检查

当前是 React 静态前端＋FastAPI＋PostgreSQL＋Neo4j＋外部模型 API。解构组的函数/游戏在浏览器 Worker 中运行；常规 AI 组旧整文件执行仍使用主线程 Pyodide，其隔离和运行能力尚需统一，不能把前者的安全保证泛化到所有入口。两组现有助手路径也不同，不为本次实验增加多 Agent、自主改库或 Redis。

工程建议而非已压测结论：4 GB 内存可作为小规模试运行起点，优先 2–4 vCPU、SSD 并保留至少 20 GB 可用磁盘及独立备份空间；8 GB 内存更有余量。4 GB 情况需实测并约束 Neo4j 堆/页缓存、数据库连接池和模型并发，不能把全部默认缓存都放开。课堂不在服务器上本地构建前端或集中执行学生游戏。服务器配置不能解决模型供应商排队和学校外网问题。

研究包按 200 条一批处理、低压缩等级、临时磁盘文件；SQL 一致性快照；数据库咨询锁限制同时生成一个包；90 秒总时限、单查询 15 秒、双格式未压缩内容上限 128 MiB，超限明确失败并要求分班导出。图谱单独只读事务，不能声称与 SQL 跨库原子一致。建议课后导出，不与全班集中求助争抢资源。

进校前仍需：真实学校电脑预加载 Pyodide；班级规模的聊天＋保存混合负载试测，记录 P50/P95、错误率、供应商限流和断网恢复；确认知情同意、未成年人数据权限、存储期限与对外共享范围；更换默认开发密码。人数、课时未知时不宣称正式实验方案已经完全定稿。

## 7. 界面约束

操作文案用学生听得懂的动词：玩一玩、记下发现、功能叫什么、画出怎么做、运行看看。一次只说当前要做的事。代码保留简短用途注释；不展示给学生模型检索轨迹、研究指标解释和工程协议长段落。重要错误与保存状态不能为了清爽而隐藏。

本轮借鉴 [VS Code 的可收起面板](https://code.visualstudio.com/docs/editing/getting-started/overview) 和 [GOV.UK 界面写作原则](https://www.gov.uk/service-manual/design/writing-for-user-interfaces)：保留原有编辑器与侧栏，减少重复标题/英文装饰；助手正文和代码分开呈现、代码可复制；表单正文放大。没有引入新的大型 UI 依赖，也没有因视觉调整改变阶段门槛或研究事件语义。
